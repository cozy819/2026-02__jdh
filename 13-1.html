1. 평가 기준1. 评价标准13-1

수행평가에서 확인하는 능력实作评价要看的能力 수행평가 3实作评价 3

  • 수행평가 2 PRD와 9회의 사용자 흐름을 실제 서비스에 연결했는가?把实作评价 2 的 PRD 与第 9 次课的用户流程接到了真实服务上吗？
  • 사용자가 대표 흐름을 따라 핵심 결과에 도달하는가?用户能沿代表流程走到核心结果吗？
  • 테스트 결과를 근거로 문제를 수정했는가?是以测试结果为依据修改问题的吗？
  • 화면의 행동이 API의 요청·응답으로 이어지고 SQLite에 기록되는 과정을 자기 서비스로 설명하는가?能用自己的服务说明画面行动如何连到 API 请求·响应，并记录到 SQLite吗？
  • AI가 한 일과 학생이 판단·확인한 일을 구분하는가?分得清 AI 做的事与学生判断、确认的事吗？
  • 개인정보·비밀정보와 불필요한 기능을 피했는가?避开了个人信息、机密信息与多余功能吗？
모든 프로젝트의 공통 기준所有项目的共同标准

SQLite에 핵심 기록을 저장하고 다시 보여 주는 흐름은 모든 프로젝트의 공통 기준입니다.把核心记录存进 SQLite 并能再展示出来，是所有项目的共同标准。

평가하지 않는 것不评价的

코드의 양, 화면의 화려함, 기능 수, 테이블 수와 DB 구조의 복잡함은 평가하지 않습니다. 기능 하나가 목적에 맞게 끝까지 이어지는 서비스가, 기능 열 개가 중간에 끊기는 서비스보다 좋습니다.代码多少、画面花哨程度、功能个数、表的数量与数据库结构的复杂度都不评价。一个功能能扣着目的走到底，好过十个功能半路断掉。

3. 문제 선택3. 选问题13-1

반드시 고칠 문제를 하나 고른다选出一个必须改的问题 핵심核心

우선순위는 다음과 같습니다. 위에 있는 것부터 봅니다.优先级如下，从上往下看。

  • 개인정보·비밀정보와 안전 문제个人信息、机密信息与安全问题
  • 사용자가 시작 방법을 알 수 없거나 핵심 결과에 도달하지 못하는 문제用户不知道怎么开始，或到不了核心结果
  • 잘못된 상황 뒤 다시 시도할 수 없는 문제出错之后无法重试
  • 저장되어야 할 기록이 새로고침·재실행 뒤 사라지는 문제该保存的记录刷新或重启后就没了
  • 행동 뒤 반응과 결과를 이해하기 어려운 문제行动之后反应与结果难以理解
  • 플랫폼을 사용하는 경우에만 발생하는 실행 문제只在使用平台时才出现的运行问题
  • 작은 안내 문장과 화면 표시 문제小的提示语与画面显示问题
한 번에 하나만一次只选一个

한 번에 가장 중요한 문제 하나만 선택합니다. 목록을 훑다가 고치기 쉬운 것부터 손대면, 정작 사용자를 막고 있는 문제가 남습니다.一次只挑最重要的那一个。扫一眼清单就先挑好改的下手，真正挡住用户的问题反而留着。

  • 오늘 고를 문제今天要选的问题
  • 이 문제가 사용자에게 주는 영향这问题对用户的影响
  • 우선순위에서 몇 번째인가在优先级里排第几

내 서비스의 사용자와 목적은 ___이야.

전체 프로젝트와 DB 구조를 다시 만들지 말고,
이 사용자 흐름을 이어지게 하는 가장 작은 수정만 제안해 줘.

사용자와 목적, 계획한 흐름, 예상과 실제, 처음 달라진 단계. 이 네 가지는 모두 이미 문서에 적혀 있습니다. 옮겨 적기만 하면 됩니다.用户与目的、计划的流程、预期与实际、第一处不同的步骤。这四样文档里都已经写好了，照抄过去就行。

반영하지 않을 제안不采纳的提议

AI가 계획서에 없는 기능, 새 패키지나 전체 재작성을 제안하면 반영하지 않습니다. “더 좋게 만들어 드릴까요?”라는 제안이 오늘은 위험합니다. 오늘의 목표는 더 좋은 서비스가 아니라 계획대로 이어지는 서비스입니다.AI 若提议计划书里没有的功能、新的包，或者整体重写，一概不采纳。“要不要帮你做得更好？”这种提议今天很危险。今天的目标不是更好的服务，而是照计划能走通的服务。

5. 재시험5. 重测13-1

같은 테스트로 재시험한다用同一套测试重测 실습实践

  • 수정 전과 같은 시작 상태와 행동인가?与改前是同样的起始状态和行动吗？
  • 예상한 서비스 반응이 같은가?预期的服务反应还是同一个吗？
  • 처음 달라졌던 단계가 이제 계획과 맞는가?当初出岔的那一步现在跟计划对得上吗？
  • 대표 사용자 흐름 전체가 계속 이어지는가?整条代表性用户流程还接得上吗？
  • 다시 방문했을 때 저장된 기록이 보이는가?再次访问时看得到已保存的记录吗？
기록을 남깁니다要留下记录

테스트 기록 파일에 수정 내용과 재시험 결과를 추가합니다. 이 기록이 13-2에서 “테스트 결과를 근거로 수정했다”를 설명하는 자료가 됩니다.在测试记录文件里补上修改内容与重测结果。这份记录就是 13-2 里说明“依据测试结果做了修改”的材料。

네 번째 항목을 빠뜨리기 쉽습니다第四条最容易漏

고친 곳만 확인하고 넘어가면, 수정이 다른 곳을 막았는지 알 수 없습니다. 반드시 처음부터 끝까지 한 번 더 실행합니다.只确认改动那一处就过去，就不知道修改有没有堵住别处。一定要从头到尾再跑一遍。

6. 표현 정리6. 打磨表达13-1

시간이 남으면 표현을 가다듬는다有余力再打磨表达 확장拓展

기능과 안전 문제가 모두 해결된 뒤에 다음을 확인합니다.功能与安全问题全部解决之后，再看下面这些。

  • 서비스 이름·목적과 시작 방법이 첫 화면에서 보이는가?服务的名称、目的与开始方法在首屏看得到吗？
  • 사용자가 다음에 할 행동을 이해할 수 있는가?用户明白接下来该做什么吗？
  • 행동 뒤 무엇이 일어났는지 알아볼 수 있는가?行动之后发生了什么看得出来吗？
  • 결과의 의미가 분명한가?结果的含义清楚吗？
  • 예외 안내가 고칠 방법과 돌아갈 길을 알려 주는가?例外提示说明了怎么改与怎么回去吗？
  • 불필요한 예시 문장과 작동하지 않는 버튼이 없는가?有没有多余的示例文字与点了没用的按钮？
  • 작은 화면 장식이 핵심 기능을 방해하지 않는가?小装饰有没有妨碍核心功能？
여기서 멈춥니다到此为止

화면 전체를 새로 만들거나 애니메이션을 추가하지 않습니다. 표현을 가다듬는 것은 글자와 배치를 고르는 일이지 다시 만드는 일이 아닙니다.不重做整个画面，也不加动画。打磨表达是挑字句、调位置，不是重做。

7. 금지 사항7. 不做的事13-1

이번 시간에 하지 않는 것这节课不做的事 핵심核心

하지 않습니다不做하면 생기는 일做了会怎样
새로운 핵심 기능 추가加新的核心功能테스트하지 않은 흐름이 제출본에 들어간다没测过的流程混进了提交版
DB 구조 전체 변경全面改动数据库结构지금까지 저장된 기록을 다시 볼 수 없게 된다此前存下的记录再也看不到
프레임워크·패키지와 프로젝트 구조 교체换框架、包与项目结构남은 시간에 다시 실행시키지 못할 수 있다剩下的时间里可能再也跑不起来
로그인·외부 API·파일 업로드 새로 추가新加登录、外部 API、文件上传계획에 없던 안전 문제가 생긴다冒出计划外的安全问题
AI에게 프로젝트 전체 재작성 요청让 AI 整体重写项目지금까지 확인한 결과가 모두 무효가 된다此前确认过的结果全部作废
PRD를 결과에 맞춰 이유 없이 바꾸기没理由地把 PRD 改成配合结果계획과 실제를 비교한 기록이 사라진다比较计划与实际的记录就没有了
달라졌다면 이유를 적습니다有出入就写理由

계획과 실제 결과가 다르면 변경 사실과 이유를 기록합니다. 계획대로 되지 않은 것은 감점 사유가 아니지만, 이유 없이 계획을 지우는 것은 다릅니다.计划与实际结果不同，就把变动与理由记下来。没能照计划做不是扣分理由，但不说理由就把计划抹掉是另一回事。

  • 실제 개인정보·비밀번호·API 키를 제외한다.排除真实的个人信息、密码、API 密钥。

12회에 만든 것과 파일명은 같지만, 오늘 수정한 내용이 반영된 새 버전입니다. 이전 ZIP을 덮어쓰거나 교사 안내에 따라 새로 올립니다.与第 12 次课那份文件名相同，但它是含今天修改的新版本。覆盖旧 ZIP，或按老师的指示重新上传。

9. 최종 실행본9. 最终运行版13-1

최종 실행본을 확인한다确认最终运行版本 실습实践

플랫폼을 사용할 수 있는 경우可以使用平台时

  1. 새 프로젝트 ZIP을 제출 버전으로 업로드한다.把新的项目 ZIP 作为提交版本上传。
  2. 파일 검증·빌드·실행 결과를 확인한다.确认文件校验、构建与运行结果。
  3. 미리보기에서 첫 화면을 연다.在预览里打开首屏。
  4. 대표 정상 흐름과 예외 뒤 회복 흐름을 한 번씩 실행한다.代表性正常流程与例外后的恢复流程各跑一遍。
  5. 재실행 뒤 SQLite에 저장된 기록을 확인한다.确认重启后 SQLite 里保存的记录。
  6. 파일 업로드 기능이 승인된 경우 허용·거부 조건을 다시 확인한다.若文件上传功能获批，再确认一次允许与拒绝的条件。

플랫폼을 사용할 수 없는 경우无法使用平台时

  1. 학생 기기에서 대표 정상 흐름과 예외 뒤 회복 흐름을 실행한다.在学生设备上跑一遍代表性正常流程与例外后的恢复流程。
  2. 최종 ZIP을 교사가 지정한 위치에 제출한다.把最终 ZIP 交到老师指定的位置。
  3. 필요하면 교사 기기에서 같은 ZIP을 다시 실행한다.需要时在老师的设备上重新运行同一个 ZIP。
  4. 플랫폼 미실시는 감점 사유로 삼지 않는다.未使用平台不作为扣分理由。

11. 정리11. 小结13-1

핵심 정리核心小结

이번 차시에서 남길 것本课时要记住的
  • 오늘은 만드는 시간이 아니라 고치는 시간이다.今天不是做的时间，是改的时间。
  • 수정의 근거는 12회의 테스트 기록이다. 느낌이 아니다.修改的依据是第 12 次课的测试记录，不是感觉。
  • 우선순위는 안전 → 핵심 결과 → 재시도 → 기록 유지 → 이해 → 표현 순이다.优先级是安全 → 核心结果 → 重试 → 记录留存 → 理解 → 表达。
  • 문제 하나 · 수정 하나 · 재시험 하나의 고리를 지킨다.守住一个问题 · 一处修改 · 一次重测的循环。
  • 수정 뒤에는 대표 흐름 전체를 처음부터 다시 확인한다.改完之后，从头再确认整条代表流程。
  • 전체 재작성·구조 교체·새 기능은 오늘 하지 않는다.整体重写、换结构、加新功能，今天都不做。
  • 계획과 결과가 다르면 지우지 말고 이유를 적는다.计划与结果不同，别抹掉，写下理由。
  • 13-1이 끝나면 기능 수정은 종료다.13-1 一结束，功能修改就到此为止。
