      2. 데이터베이스2. 数据库7-1

      데이터베이스는 서비스의 기억 장소다数据库是服务记东西的地方 핵심核心

      데이터베이스(DB)는 서비스가 나중에 다시 꺼내 볼 수 있도록 정보를 모아 두는 곳입니다. 해킹당한 은행의 고객 정보도 여기에 있었습니다. 앞에서 F5를 누르자 비어 버린 연습 칸에는 이 저장하는 곳이 없었습니다.数据库（DB）是把信息存起来、让服务以后还能再取出来看的地方。被黑客攻击的银行，客户信息也存在这里。前面一按 F5 就空了的练习栏，就是缺了这个保存的地方。

      Data · 데이터Data · 数据자료 · 사실, 숫자, 글资料 · 事实、数字、文字
      +
      Base · 베이스Base · 基地바탕 · 모아 두는 기지基础 · 聚集存放的基地
      =
      DatabaseDatabase자료를 모아 두고 꺼내 쓰는 곳收集资料、需要时取用的地方

      Base는 「기초·바탕」이라는 뜻으로 익숙하지만, 남극 「세종기지」나 야구의 1루 베이스처럼 무언가가 모여 있고 거기서 출발하는 곳이라는 뜻도 있습니다. 그래서 Database는 자료를 한곳에 모아 두고, 서비스가 필요할 때 거기서 꺼내 쓰는 바탕입니다.Base 大家熟悉的是“基础”的意思，但它也有像南极“世宗基地”、棒球一垒垒包那样，东西聚在一起、从那里出发的地方的意思。所以 Database 就是把资料集中存放在一处，服务需要时从那里取用的基础。

      두 단어가 한 단어가 되기까지从两个词变成一个词

      이 말은 1960년대 초 미국에서 군사용 컴퓨터 시스템을 만들던 연구소(SDC)가 「data base」라고 두 단어로 띄어 쓰면서 시작되었습니다. 1963년 이 연구소가 「컴퓨터 중심 data base의 개발과 관리」라는 이름의 학술 모임을 열면서 널리 퍼졌고, 많이 쓰이자 나중에 database 한 단어로 붙여 쓰게 되었습니다.这个词始于 20 世纪 60 年代初：美国一家开发军用计算机系统的研究所（SDC）分成两个词写成“data base”。1963 年，这家研究所举办了名为“以计算机为中心的 data base 的开发与管理”的学术会议，这个词由此传开；用得多了，后来就连成一个词写作 database。

      2. 데이터베이스2. 数据库7-1

      데이터베이스는 크게 두 가지다数据库大致分两类 핵심核心

      데이터베이스는 정보를 저장하는 모양에 따라 크게 두 가지로 나눕니다. 표에 저장하는 RDBMS와, 표가 아닌 모양으로 저장하는 NoSQL입니다. 은행의 고객 정보처럼 항목이 정해진 기록은 대부분 표에 저장합니다.数据库按保存信息的样子，大致分成两类：存进表里的 RDBMS，和不用表来保存的 NoSQL。像银行客户信息这样项目固定的记录，大多存在表里。

      RDBMS · 관계형 데이터베이스RDBMS · 关系型数据库

      정보를 표에 저장하고, 표와 표를 서로 이어 둡니다. 가장 많이 쓰이는 데이터베이스이고, 표 하나는 여러분이 아는 엑셀 표와 같은 모양입니다.把信息存进表里，并把表和表连起来。这是用得最多的数据库，一张表的样子就和大家熟悉的 Excel 表一样。

      학년年级반班번호号이름姓名
      231김민준金民俊
      232이서연李瑞妍
      NoSQL · 표가 아닌 데이터베이스NoSQL · 不用表的数据库

      RDBMS가 아닌 데이터베이스를 모두 묶어 부르는 이름입니다. 문서, 「키 : 값」, 그래프처럼 저장하는 모양이 여러 가지이고, 쓰임에 따라 고릅니다.不是 RDBMS 的数据库，统称 NoSQL。保存的样子有很多种，比如文档、“键 : 值”、图，按用途来选。

      { "grade": 2, "class": 3,
  "no": 1, "scores": [85, 92] }
      이 수업에서는 RDBMS를 쓴다这门课用 RDBMS

      RDBMS의 R은 Relational, 「관계형」입니다. 왜 이런 이름인지는 학생 표와 성적 표를 직접 이어 본 뒤에 다시 봅니다. 11회에는 SQLite라는 RDBMS에 연결합니다.RDBMS 的 R 是 Relational，“关系型”。为什么叫这个名字，等亲手把学生表和成绩表连起来之后再来看。第 11 次课会连接一个叫 SQLite 的 RDBMS。

      3. 표·행·열3. 表·行·列7-1

      RDBMS의 표는 엑셀 성적표와 닮았다RDBMS 的表和 Excel 成绩表很像 핵심核心

      엑셀로 성적표를 만들면 가로 한 줄에 학생 한 명의 점수를 적고, 세로 한 칸에는 국어·수학 같은 과목 하나를 모읍니다. 엑셀 왼쪽의 1, 2, 3이 행(row) 번호이고 위쪽의 A, B, C가 열(column)이었습니다. RDBMS의 표도 똑같이 행 하나가 기록 하나, 열 하나가 그 기록의 항목입니다.用 Excel 做成绩表时，横着一行写一个学生的分数，竖着一列放语文、数学这样的一门科目。Excel 左边的 1、2、3 是行（row）号，上面的 A、B、C 是列（column）。RDBMS 的表也一样：一行是一条记录，一列是这条记录的一个项目。

      엑셀로 만든 성적표用 Excel 做的成绩表
      ABCD
      1이름姓名국어语文수학数学영어英语
      2김민준金民俊859278
      3이서연李瑞妍907488
      4김민준金民俊778195

      주황 줄 = 행 하나 = 학생 한 명의 점수   파란 칸 = 열 하나 = 수학 橙色那一行 = 一行 = 一个学生的分数   蓝色那一列 = 一列 = 数学

      표를 볼 때 첫 질문看表时的第一个问题

      「이 표의 한 행은 무엇인가?」에 한 문장으로 답할 수 있어야 합니다. 이 성적표라면 「학생 한 명의 점수」입니다. 그런데 2행과 4행은 이름이 같습니다. 누가 누구인지 어떻게 구별할까요? 다음 쪽에서 봅니다.要能用一句话回答“这张表的一行是什么？”。这张成绩表的答案是“一个学生的分数”。可是第 2 行和第 4 行名字一样，怎么分清谁是谁？下一页来看。

      4. 기본키4. 主键7-1

      학번 20301이 한 명을 딱 집어낸다学号 20301 能准确指出一个人 핵심核心

      학교에 김민준이 두 명이어도 「2학년 3반 1번」이라고 부르면 딱 한 명입니다. 이 세 숫자를 붙여 쓴 것이 학번 20301입니다. 표에서 이렇게 행 하나를 딱 집어내는 열을 기본키(PK, Primary Key)라고 하고, 학생 표에서는 학번이 기본키입니다.学校里就算有两个金民俊，只要说“2 年级 3 班 1 号”，就只指一个人。把这三个数字连起来写，就是学号 20301。表里这样能准确指出一行的列，叫主键（PK，Primary Key）。在学生表里，学号就是主键。

      Primary Key라는 이름“Primary Key”这个名字

      Primary는 영어로 「첫째의, 가장 중요한」이라는 뜻이고, Key는 열쇠입니다. 그래서 Primary Key는 이 행을 대표하는 가장 중요한 열쇠, 기본키입니다.Primary 在英语里是“第一的、最重要的”，Key 是钥匙。所以 Primary Key 就是代表这一行的最重要的钥匙，也就是主键。

      기본키가 지킬 것主键要守的规矩

      한 표 안에서 겹치지 않고, 비어 있지 않아야 합니다. 이름은 같을 수 있어서 기본키로 쓰지 않습니다.在一张表里要不重复、不为空。名字可能相同，所以不拿来当主键。

      5. 외래키5. 外键7-1

      성적은 따로 표를 만들고 학번으로 잇는다成绩另做一张表，用学号连起来 핵심核心

      시험을 볼 때마다 성적이 쌓이는데, 그때마다 학생 표에 이름과 반을 다시 적으면 같은 정보가 되풀이됩니다. 그래서 성적은 성적 표로 따로 만들고, 어느 학생의 성적인지는 학번만 적어 학생 표를 가리킵니다. 이렇게 다른 표의 기본키를 가져와 적은 열을 외래키(FK, Foreign Key)라고 합니다.每次考试成绩都会越积越多，要是每次都把姓名、班级重新写进学生表，同样的信息就会一再重复。所以成绩另做一张成绩表，是哪个学生的成绩，只写学号，指向学生表。像这样把别的表的主键拿过来写的列，叫外键（FK，Foreign Key）。

      Foreign Key라는 이름“Foreign Key”这个名字

      Foreign은 영어로 「외국의, 바깥의」라는 뜻입니다. 성적 표 안에 있지만 바깥, 곧 다른 표(학생 표)에서 가져온 열쇠라서 Foreign Key, 외래키(밖에서 온 키)입니다.Foreign 在英语里是“外国的、外面的”。它虽然在成绩表里，却是从外面、也就是从别的表（学生表）拿来的钥匙，所以叫 Foreign Key，外键（从外面来的键）。

      6. 1:N6. 1:N7-1

      7. JOIN7. JOIN7-1

      학생과 성적을 표 두 개로 나누고, 학번이라는 같은 값으로 둘을 엮어 두었습니다. 이렇게 표와 표의 관계로 정보를 다루기 때문에 관계형(Relational) 데이터베이스, RDBMS라고 부릅니다. 이름이 같은 두 김민준도 학번이 달라 섞이지 않습니다. JOIN을 쓰는 문법(SQL)은 배우지 않습니다.把学生和成绩分成两张表，用学号这个相同的值把它们串起来。正因为用表和表之间的关系来处理信息，所以叫关系型（Relational）数据库，也就是 RDBMS。两个同名的金民俊，学号不同，也不会混在一起。不学写 JOIN 的语法（SQL）。

      표는 하나로 충분한 경우가 많다很多时候一张表就够了

      2. 표의 열 이름과 예시 세 줄, 그 아래 「한 행은 ~」 문장까지 끝까지 읽는다.把表的列名、三行示例，连同下面那句“一行是……”一直读到最后。
      10. 읽고 검토10. 阅读并检查7-1

      네 가지를 읽고, 다르면 다시 말한다读这四件事，不对就再告诉 AI 핵심核心

      AI가 그린 표는 출발점입니다. 아래 네 가지를 내 눈으로 확인하고, 다르면 AI에게 다시 말해 고치게 합니다. AI가 파일을 고쳐도 괜찮습니다. 고친 뒤에 다시 끝까지 읽는 것이 오늘의 연습입니다.AI 画的表只是起点。用自己的眼睛确认下面四件事，不对就再告诉 AI，让它改。AI 改文件没关系。改完之后再从头读到尾，就是今天的练习。

      읽고 확인할 것要读并确认的다르면 이렇게 말한다不对就这样说
      한 행은 무엇인가 — 「한 행은 ~」 문장이 내 서비스의 기록 하나를 말하나一行是什么 — “一行是……”这句话说的是不是自己服务的一条记录「한 행이 무엇인지 더 쉬운 말로 다시 적어 줘.」「请用更简单的话重新写一行代表什么。」
      기본키 — 표마다 한 행을 집어낼 열(id나 여러 칸의 조합)이 있나主键 — 每张表有没有能指出一行的列（id 或几格的组合）「표마다 기본키가 무엇인지 알려 주고, 없으면 넣어 줘.」「请告诉我每张表的主键是什么，没有就加上。」
      실제 개인정보 — 예시에 진짜 이름·전화번호·주소가 들어갔나真实个人信息 — 示例里有没有真实的姓名、电话、地址「예시에서 실제 개인정보를 빼 줘.」「请把示例里的真实个人信息删掉。」
      표의 수 — 섞인 대상이 있거나 표가 세 개를 넘나表的数量 — 有没有混在一起的对象，表是不是超过三张「표를 하나로 줄일 수 있는지 이유와 함께 알려 줘.」「请告诉我能不能减成一张表，并说明理由。」
      이 파일은 다음 시간의 재료다这个文件是下节课的材料

      표가 둘 이상이면 외래키 열이 여러 개가 붙는 쪽에 있는지도 봅니다. 데이터_예시.md는 제출물이 아니고, 7-2에서 PRD의 5항을 쓸 때 AI와 내가 함께 보는 재료입니다.如果有两张以上的表，还要看外键列是不是在“多”的那一边。데이터_예시.md 不是提交物，而是 7-2 写 PRD 第 5 项时，自己和 AI 一起看的材料。

      11. 막힐 때11. 卡住时7-1

      이럴 때는 이렇게 한다遇到这些情况这样做 필요할 때需要时

      연습 칸을 해 보고 AI에게 표를 맡기다 보면 막히는 자리가 비슷합니다. 내 상황과 같은 줄을 찾아 오른쪽대로 해 봅니다. 그래도 안 되면 손을 듭니다.试练习栏、把表交给 AI 时，卡住的地方都差不多。找到和自己情况一样的那一行，照右边做。还不行就举手。

      이런 상황이라면如果是这些情况
      F5를 눌렀더니 교과서 첫 쪽으로 간다按了 F5，教材跳回了第一页목차에서 「사라지는 것」을 눌러 연습 칸으로 돌아갑니다. 목록이 비어 있으면 맞게 한 것입니다.在目录里点“消失的东西”，回到练习栏。列表是空的，就说明做对了。
      F5를 눌렀는데 입력칸에 글자가 남아 있다按了 F5，输入框里还有字브라우저가 입력칸 글자만 잠깐 기억해 둔 것입니다. 추가한 목록이 사라졌는지 봅니다.是浏览器暂时记住了输入框里的字。看看添加的列表有没有消失。
      AI가 PRD.md를 찾지 못한다고 한다AI 说找不到 PRD.md터미널 줄 끝이 …\06>인지 봅니다. 아니라면 06 폴더를 다시 열고 새 터미널에서 OpenCode를 엽니다.看终端提示符结尾是不是 …\06>。不是的话，重新打开 06 文件夹，在新终端里打开 OpenCode。
      미리 보기에 표가 아니라 | 기호가 그대로 보인다预览里不是表，而是原样显示 | 符号「데이터_예시.md의 표를 Markdown 표 형식으로 고쳐 줘」를 보내고 미리 보기를 다시 봅니다.发「请把 데이터_예시.md 里的表改成 Markdown 表格式」，再看一次预览。
      AI가 열을 너무 많이 만들었다AI 建的列太多了「꼭 필요한 열만 남겨 다섯 개 이하로 줄여 줘」를 보냅니다.发「请只留下必要的列，减到五个以内」。
      FreeUsageLimitError나 429가 나오고 답이 멈춘다出现 FreeUsageLimitError 或 429，回答停住무료 모델의 사용량이 잠깐 찬 것입니다. 1~2분 기다렸다가 같은 요청을 다시 보냅니다. 계속되면 손을 듭니다.是免费模型的用量暂时满了。等 1~2 分钟再发一次同样的请求。一直这样就举手。
      12. 정리12. 小结7-1

      오늘 남길 것今天要记住的

      오늘은 서비스가 정보를 표에 나누어 기억하고, 보여 줄 때 합친다는 것을 보았습니다. 그리고 내 서비스가 기억할 것을 AI와 표로 그려 직접 읽고 검토했습니다. 다음 시간에는 이 표를 보며 PRD의 5. 데이터를 씁니다.今天看到了服务把信息分在几张表里记住、显示时再合起来。还和 AI 一起把自己的服务要记住的东西画成表，亲自读过、检查过。下节课就看着这张表写 PRD 第 5 项「数据」。

      오늘의 핵심今天的重点
      • 새로 고침하면 사라지는 서비스는 아무것도 저장하지 않은 것이다. 기억하려면 데이터베이스에 저장한다.一刷新就消失的服务，是什么都没保存。要记住，就要存进数据库。
      • 표의 한 행은 기록 하나, 열은 그 기록의 항목이다. 먼저 「한 행은 무엇인가」를 말한다.表的一行是一条记录，列是这条记录的项目。先说出“一行是什么”。
      • 기본키(Primary Key, 가장 중요한 열쇠)는 학번 20301처럼 행 하나를 집어낸다. 두 칸 이상을 합치면 복합 기본키다.主键（Primary Key，最重要的钥匙）像学号 20301 那样准确指出一行。两格以上合起来就是复合主键。
      • 되풀이되는 정보는 표를 나누고, 외래키(Foreign Key, 다른 표에서 가져온 열쇠)로 다른 표의 기본키를 가리킨다. 1:N이면 외래키는 N 쪽에 둔다.重复的信息就拆表，用外键（Foreign Key，从别的表拿来的钥匙）指向另一张表的主键。1:N 时外键放在 N 那一边。
      • JOIN은 학번처럼 같은 값을 따라 나눠 둔 표를 엮어서 보는 것이다. 표는 하나로 충분한 경우가 많다.JOIN 就是顺着学号这样的相同值，把分开的表串起来看。很多时候一张表就够了。
