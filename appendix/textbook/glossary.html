프로그램 뒤편의 이야기

진도를 더 나가기 위한 내용이 아닙니다. 수업에서 만난 낱말 하나를 5~7분 동안 조금 더 깊게 살펴봅니다.

평가하지 않습니다. 본 수업과 실습을 모두 마친 날에만 선택해서 읽습니다.

2주차 · CPU01

코드 한 줄을 실제로 처리하는 것은 무엇일까?

장면

VS Code에서 실행 버튼을 누르면 화면에는 곧바로 결과가 나타납니다. 그 짧은 순간에도 컴퓨터 안에서는 수많은 명령이 잘게 나뉘어 처리됩니다.

CPU는 프로그램의 명령을 해석하고 계산과 제어를 수행하는 중앙처리장치입니다. Python이 우리가 쓴 코드를 실행 가능한 명령으로 이어 주면, 그 명령은 결국 CPU에서 처리됩니다.

Python 코드사람이 읽기 쉬운 명령
→
실행 과정더 작은 명령으로 변환
→
CPU계산과 제어

오해: CPU 혼자 모든 일을 하지는 않습니다. 메모리·저장장치·운영체제와 함께 움직입니다.

기억할 문장

CPU는 프로그램의 명령을 실제 계산과 제어로 처리하는 장치다.

3주차 · 메모리02

변수에 넣은 값은 실행하는 동안 어디에 있을까?

책상 위에는 지금 읽는 책과 메모를 펼쳐 두고, 책장에는 오래 보관할 자료를 넣습니다. 컴퓨터도 지금 사용하는 내용과 오래 남길 내용을 서로 다른 곳에 둡니다.

RAM · 작업 책상

실행 중인 프로그램과 지금 필요한 값을 빠르게 읽고 씁니다.

SSD · 책장

프로그램을 닫거나 전원을 꺼도 파일을 오래 보관합니다.

변수·list·dict의 값은 프로그램이 실행되는 동안 주로 메모리에 놓입니다. 오래 남겨야 한다면 파일이나 데이터베이스에 저장해야 합니다.

오해: RAM이 많아지면 모든 프로그램이 같은 비율로 빨라지는 것은 아닙니다. 책상이 넓어져도 일하는 사람의 속도와 일의 종류가 함께 영향을 줍니다.

기억할 문장

메모리는 실행 중인 프로그램이 지금 사용하는 내용을 펼쳐 두는 작업 공간이다.

4주차 · 라이브러리03

그래프의 선과 글자를 모두 직접 만들어야 할까?

요리사가 냄비와 칼부터 만들지 않듯 개발자도 자주 쓰는 기능을 매번 처음부터 만들지 않습니다. 이미 검증된 기능을 가져와 자기 문제에 맞게 사용합니다.

pandas

행과 열로 된 표 데이터를 읽고 확인하고 정리합니다.

Matplotlib

막대·선·산점도 같은 그래프를 그립니다.

라이브러리는 다른 프로그램에서 불러와 사용할 수 있도록 미리 만들어 둔 코드와 기능의 모음입니다. import는 설치된 라이브러리를 현재 코드에서 사용하겠다는 뜻입니다.

오해: 내부를 모두 외울 필요는 없지만 입력·결과·사용 조건은 확인해야 합니다. 버전이 달라지면 같은 코드가 다르게 움직일 수도 있습니다.

기억할 문장

라이브러리는 필요한 기능을 다시 만들지 않고 가져다 쓸 수 있게 정리한 코드 모음이다.

6주차 · 서버04

서버는 아주 크고 비싼 컴퓨터일까?

식당에서 손님이 주문하면 주문은 주방으로 전달되고 완성된 음식이 돌아옵니다. 웹서비스에서도 화면이 요청을 보내면 다른 프로그램이 그 요청을 처리해 결과를 돌려줍니다.

화면요청을 보냄
→
서버규칙에 따라 처리
→
화면결과를 받음

서버는 다른 프로그램의 요청을 받아 정해진 기능이나 데이터를 제공하는 프로그램 또는 그 역할을 맡은 컴퓨터입니다.

오해: 서버는 반드시 데이터센터의 거대한 기계를 뜻하지 않습니다. 일반 컴퓨터도 서버 프로그램을 실행하면 그 순간 서버 역할을 할 수 있습니다.

기억할 문장

서버는 모양이 아니라 다른 프로그램의 요청을 받아 처리하는 역할로 구분한다.

7주차 · 데이터베이스05

메모장이나 Excel 파일이 있는데 왜 데이터베이스를 쓸까?

학생 명단 한 장은 파일로 관리할 수 있습니다. 하지만 여러 사람이 동시에 기록을 추가하고, 사용자·게시글·댓글처럼 서로 연결된 정보를 정확히 찾아야 한다면 관리 규칙이 필요합니다.

데이터베이스는 데이터를 일정한 구조로 저장하고 필요한 조건에 따라 추가·조회·수정·삭제할 수 있게 관리하는 체계입니다.

파일

한 덩어리의 문서나 표를 저장하기 좋습니다.

데이터베이스

많은 기록의 구조·관계·접근 규칙을 함께 관리합니다.

오해: 데이터베이스는 표의 모양만 뜻하지 않으며 Excel 파일과 완전히 같지 않습니다.

기억할 문장

데이터베이스는 데이터를 쌓아 두는 곳을 넘어 구조와 규칙에 따라 찾고 관리하는 체계다.

9주차 · 프레임워크06

웹서비스의 모든 파일과 규칙을 처음부터 정해야 할까?

건물을 지을 때 공법과 기본 골조가 있으면 작업 순서와 각 부분의 자리가 분명해집니다. 프로그램도 빈 폴더보다 기본 구조와 규칙이 있을 때 여러 기능을 일관되게 붙이기 쉽습니다.

프레임워크는 프로그램의 전체 구조와 실행 흐름, 확장 방식을 제공하는 개발 기반입니다. 수업에서는 제공된 프로젝트 템플릿과 프레임워크 위에서 AI와 기능을 추가합니다.

오해: 프레임워크는 단순히 ‘큰 라이브러리’가 아닙니다. 라이브러리는 우리가 필요한 기능을 부르고, 프레임워크는 정해진 흐름 속에서 우리가 작성한 부분을 불러 실행하는 경우가 많습니다.

기억할 문장

프레임워크는 프로그램을 어떤 구조와 흐름으로 만들지 기본 틀을 제공한다.

10주차 · API07

서로의 내부 코드를 모르는데 어떻게 기능을 부탁할까?

손님은 주방 안의 조리법을 몰라도 메뉴와 주문 형식에 맞춰 요청하면 음식을 받을 수 있습니다. 프로그램도 상대의 내부를 직접 건드리지 않고 약속된 접점을 사용합니다.

요청주소·방법·보낼 값
→
API정해진 접점과 규칙
→
응답결과 또는 오류

API는 한 프로그램이 다른 프로그램의 기능이나 데이터에 정해진 방식으로 요청하고 결과를 받을 수 있게 한 접점과 규칙입니다.

오해: API는 인터넷 주소 하나만을 뜻하지 않으며, 외부 유료 AI 서비스만을 의미하지도 않습니다.

기억할 문장

API는 프로그램끼리 기능과 데이터를 요청하고 받을 때 지키는 접점과 규칙이다.

11주차 · 상태08

새로고침 뒤에도 남는 내용과 사라지는 내용은 무엇이 다를까?

프로그램이 현재 무엇을 기억하고 있는지를 상태(State)라고 부릅니다. 로그인 여부, 선택한 메뉴, 장바구니, 작성 중인 글도 모두 다음 동작을 바꾸는 상태입니다.

잠깐 기억

현재 화면이나 메모리에서만 사용해 새로고침·종료 뒤 사라질 수 있습니다.

오래 기억

파일이나 SQLite 같은 데이터베이스에 저장해 다시 불러옵니다.

오해: 화면에 보인다고 모두 영구 저장된 것은 아닙니다. 어디에 저장했는지에 따라 유지되는 범위가 달라집니다.

기억할 문장

상태는 프로그램이 현재 기억하고 있으며 다음 동작에 사용하는 값과 상황이다.

12주차 · 버그와 디버깅09

왜 프로그램의 문제를 벌레라는 뜻의 ‘버그’라고 부를까?

1947년 하버드의 Mark II 컴퓨터를 다루던 기술자들은 릴레이에 끼어 있던 나방을 발견했습니다. 나방을 작업일지에 붙인 이 사건은 컴퓨터 버그를 설명하는 가장 유명한 일화가 됐습니다.

정확한 단서: ‘버그’라는 말은 이 사건에서 처음 만들어진 것이 아닙니다. 기계 결함을 버그라고 부르는 표현은 그전부터 있었고, 그레이스 호퍼 개인이 나방을 처음 발견했다고 단정하지도 않습니다.

버그는 프로그램이 의도하거나 요구한 것과 다르게 움직이게 만드는 결함입니다. 디버깅은 문제의 발생 조건을 다시 만들고 원인을 좁혀 수정한 뒤 재확인하는 과정입니다.
