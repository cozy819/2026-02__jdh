1. 목적교사용

이 문서가 다루는 것

9회 사용자 흐름 설계와 10~13회 서비스 구현 수업 전에 교사가 준비해야 할 AI 개발 조건, 표준 프로젝트, 실행 환경, 데이터 저장 도구, 제출 자료와 대체 운영 절차를 정리합니다.

전제

학생은 전문 개발자가 되는 것을 목표로 하지 않는다.

코드를 처음부터 작성하거나 개발 환경을 설계하기보다, 수행평가 2에서 작성한 PRD를 기준으로 AI가 만든 결과를 실행·확인·수정 요청·테스트하는 데 집중합니다.

학생에게 배포하지 않습니다

이 문서는 교사용입니다. 같은 폴더의 09-0.html(AI 개발 조건)은 학생과 AI가 함께 읽는 자료이므로 배포해도 됩니다.

2. 개발 방향교사용

수업에서 고정할 개발 방향

  • 초반 Python 학습과 9~13회 웹서비스 구현 단계를 분리한다.
  • 9회에는 사용자 흐름과 개발 계획을 확정하며 코드를 작성하지 않는다.
  • 실제 서비스 개발은 10회부터 시작하고 Python을 사용하지 않는다.
  • 학생 작품은 교사가 제공한 표준 Next.js 프로젝트 하나에서 만든다.
  • 프론트엔드와 백엔드를 별도 프로젝트로 나누지 않는다.
  • 화면·내부 API·SQLite의 역할은 구분하되 프론트엔드와 백엔드를 별도 프로젝트로 연결하는 절차는 가르치지 않는다.
  • 학생이 프레임워크, 패키지, 포트, DB 경로와 배포 방식을 선택하거나 설정하지 않는다.
  • 서비스마다 핵심 기능은 한 가지로 제한한다.
  • 모든 작품은 핵심 기능과 관련된 의미 있는 기록을 하나 이상 SQLite에 저장하고 다시 보여 준다.
  • 한 테이블로 충분하면 늘리지 않으며, DB 사용을 보여 주기 위한 가짜 기록을 만들지 않는다.
  • 로그인·결제·외부 API·관리자 기능은 기본 수업 범위에서 제외한다.
  • 파일 업로드는 핵심 기능에 꼭 필요하고 교사가 승인한 작품만 선택적으로 허용한다.
학생에게 쓸 용어

화면의 행동, API에 보내는 요청, API가 돌려주는 응답, SQLite에 남는 기록의 연결을 우선 사용합니다.

프론트엔드, 백엔드, 포트, CORS, 빌드, 마이그레이션, 리버스 프록시 등은 결과를 이해하는 데 꼭 필요한 경우에만 짧게 설명합니다.

4. 표준 프로젝트교사용

표준 Next.js 프로젝트의 기본 원칙

  • 모든 학생이 같은 시작 파일을 사용한다.
  • 한 프로젝트 안에서 화면과 서버 기능이 함께 작동한다.
  • 학생이 수정해도 되는 영역과 수정하면 안 되는 설정 영역을 구분한다.
  • AI가 전체 프로젝트를 다시 만들거나 패키지를 임의로 추가하지 않도록 프로젝트 안내 파일에 제한을 적는다.
  • 모든 작품이 같은 SQLite 기반 템플릿을 사용한다.
  • 학생 서비스와 관계없는 가짜 기록을 넣지 않고 PRD의 후보 테이블을 기준으로 최소 기록만 연결한다.
  • 로컬 실행과 플랫폼 실행에 같은 코드가 사용되어야 한다.

5. 배포·플랫폼교사용

배포와 플랫폼 운영 원칙

학생에게 외부 호스팅 서비스 가입과 공개 배포를 요구하지 않습니다. 플랫폼 업로드는 배포 기술을 배우는 활동이 아니라 제출한 작품이 다른 환경에서도 실행되는지 확인하는 절차로 다룹니다.

  • 학생은 외부 배포 계정을 만들지 않는다.
  • 학생은 서버, 도메인, 포트와 인증서를 설정하지 않는다.
  • 교사 플랫폼이 ZIP 검증·빌드·실행·미리보기를 담당한다.
  • 외부 공개는 교사가 승인한 작품과 버전에만 적용한다.
  • 공개 주소에는 실제 학번과 학생 실명을 사용하지 않는다.
  • 플랫폼 실행 성공 여부만으로 수행평가 결과를 결정하지 않는다.
  • 플랫폼 장애나 교사 준비 미완료는 학생 감점 사유가 될 수 없다.
플랫폼 준비가 되지 않았을 때의 대체 방식
  1. 학생은 로컬에서 핵심 기능과 테스트 결과를 확인한다.
  2. 표준 파일명의 프로젝트 ZIP을 제출한다.
  3. 교사는 제출 ZIP과 학생 기기의 로컬 실행 결과를 확인한다.
  4. 필요한 경우 교사 기기에서 제출본을 다시 실행한다.
  5. 플랫폼 미리보기 항목은 미실시로 기록하고 평가에서 제외한다.

  • 수행평가 2로 제출된 모든 PRD를 미리 읽고 구현 가능성을 1차 분류한다.
  • 모든 PRD에 핵심 기능과 연결된 의미 있는 기록, 기록이 생기는 행동과 다시 보는 순간이 있는지 확인한다.
  • 외부 AI·유료 키·소셜 로그인·외부 DB·파일 업로드가 포함된 아이디어를 표시한다.
  • 그대로 만들기 어려운 학생에게 제시할 작은 대안 한두 개를 준비한다.
  • 학생이 사용하는 AI 도구가 수업 개발 조건·PRD·Markdown 문서를 읽을 수 있는지 확인한다.
  • 학생 계정의 모델 사용 한도와 로그인 상태를 확인하고, 사용할 도구를 하나로 확정한다.
  • 특정 AI 도구 이름에 의존하지 않도록 같은 조건과 요청문을 쓸 수 있게 준비한다.
6. 준비 게이트교사용

수업 전 필수 준비 게이트(이어서)（续）

10회 전

  • 2회에 설치한 Node.js와 npm이 학생 기기에서 계속 실행되는지 다시 확인한다.
  • Next.js 템플릿이 사용할 Node.js 버전과 학생 기기의 버전이 맞는지 확인한다.
  • 템플릿의 의존성을 수업 중 인터넷 다운로드에 의존하지 않도록 설치 방식과 로컬 캐시를 준비한다.
  • 학생이 실행할 명령은 한 개로 고정하고 교사용 설치·복구 명령은 별도로 둔다.
  • 최소 사양 수업용 노트북에서 Next.js와 AI 도구를 함께 실행해 속도와 메모리를 확인한다.
  • 한 테이블에 핵심 기록을 저장·조회하는 정상 예제를 준비한다.
  • 서비스와 관계없는 가짜 기록을 넣은 잘못된 예시도 비교용으로 준비한다.
  • 깨끗한 폴더에 템플릿을 복사하여 처음부터 실행하는 과정을 최소 두 번 확인한다.

11회 전

  • SQLite Viewer가 학생 기기에서 설치·실행되는지 확인한다.
  • Prisma 또는 DB 구조 변경 명령은 학생이 직접 조합하지 않도록 템플릿에 고정한다.
  • 각 학생의 PRD에서 처음 연결할 후보 테이블과 저장·조회 흐름을 미리 표시한다.
  • 파일 업로드를 허용할 학생과 허용하지 않을 학생을 수업 전에 확정한다.

7. 템플릿 검증교사용

배포 전 템플릿 검증

학생에게 배포하기 전 깨끗한 수업용 환경에서 다음을 직접 확인합니다.

  • 새 폴더에 복사한 뒤 안내된 명령 하나로 실행된다.
  • 학생이 보는 로컬 주소가 하나다.
  • 다른 학생 프로젝트와 동시에 실행해도 교사가 대응할 수 있다.

  • 빈 입력 안내가 작동한다.
  • 핵심 기록 저장 예시는 재실행 후에도 데이터가 남는다.
  • 서비스와 관계없는 가짜 기록을 저장하지 않는다.
  • SQLite Viewer에서 DB를 읽기 전용으로 확인할 수 있다.
  • ZIP에 불필요한 대용량 파일과 비밀정보가 들어가지 않는다.
  • 제출 ZIP을 새 폴더에 풀어 다시 실행할 수 있다.
  • 플랫폼이 같은 ZIP을 검증·빌드·실행할 수 있다.
  • 플랫폼이 실패해도 로컬 제출본과 이전 버전이 보존된다.

11. 준비물교사용

준비물 관리표(이어서)（续）

핵심 원칙

학생은 사용자 흐름을 먼저 설계하고 10회부터 하나의 프로젝트, 하나의 실행 명령, 하나의 로컬 주소로 구현한다. 모든 작품은 핵심 기능의 의미 있는 기록을 SQLite에 저장하고 다시 보여 주되, 포트·DB 경로·빌드·배포는 교사가 준비한 템플릿과 플랫폼이 처리한다.

플랫폼은 수업 결과를 보여 주고 제출을 돕는 도구이며, 플랫폼 자체의 성공 여부를 학생의 개발 역량으로 평가하지 않는다.
