오늘의 원칙今天的原则

모든 프로젝트가 AI와 함께 사용자 흐름에 SQLite 데이터 기억 기능을 연결합니다. 기록을 남기고 다시 확인하는 흐름을 실행한 뒤, SQLite Viewer에서 같은 정보가 실제로 저장되었는지 확인합니다.每个项目都要和 AI 一起，把 SQLite 数据记忆功能接到用户流程上。跑一遍“留下记录、再次查看”的流程，然后在 SQLite Viewer 里确认同一份信息是否真的被保存。

① 기준 확인기록 · 행동 · 다시 보는 순간① 确认基准记录 · 行为 · 再看的时刻
▼
② AI에게 전달 · 대조제안을 계획서와 맞춰 본다② 交给 AI 并对照把提议与计划书对上
▼
③ 화면에서 확인남기고 → 다시 본다③ 在画面上确认留下 → 再看到
▼
④ DB와 재실행으로 확인행이 있는가 · 껐다 켜도 있는가④ 用数据库与重启确认行在不在 · 关掉再开还在不在
확인이 세 번입니다要确认三次

화면에서 한 번, DB에서 한 번, 재실행 뒤 한 번. 세 번 모두 통과해야 “기억한다”라고 말할 수 있습니다. 화면에만 보이는 것은 아직 기억이 아닙니다.画面上一次、数据库里一次、重启之后一次。三次都过了，才能说“它记住了”。只在画面上看得到，还不算记忆。

1. 기록 확인1. 确认记录11-2

저장할 핵심 기록을 다시 확인한다再确认一遍要保存的核心记录 핵심核心

  • 핵심 기능을 실행하면 생기는 기록执行核心功能会产生的记录
  • 그 기록에서 꼭 남길 정보这条记录里一定要留的信息
  • 사용자가 다시 보는 때用户再看它的时候
  • 저장하지 않을 개인정보·불필요한 값不保存的个人信息与多余的值
  • 먼저 연결할 후보 테이블先接上的候选数据表
즉시 결과만 보여 주는 서비스도 마찬가지입니다只即时展示结果的服务也一样

계산 · 변환처럼 결과를 즉시 보여 주는 서비스도 ‘입력과 결과의 최근 기록’처럼 핵심 기능과 연결된 최소 기록을 남깁니다.像计算、换算这种即时给出结果的服务，也要留下“输入与结果的最近记录”这样与核心功能相连的最小记录。

가짜 기록을 추가하지 않습니다不加假记录

DB 사용을 보여 주기 위한 가짜 방문 횟수나 서비스와 관계없는 메모를 추가하지 않습니다.不要为了显示用了数据库而加假的访问次数，或与服务无关的备注。

2. 시작 상태2. 起始状态11-2

저장 연결 전 상태를 확인한다接保存之前先确认状态 실습实践

  • 프로젝트가 실행된다.项目能运行。
  • 첫 화면이 열린다.第一个画面能打开。
  • 핵심 기능 한 가지가 작동한다.那一个核心功能能用。
  • 대표 정상 흐름과 핵심 예외 흐름이 작동한다.代表性正常流程与核心例外流程都能跑。
  • PRD와 9회 개발 계획에서 기억할 정보와 다시 보는 순간을 찾았다.从 PRD 与第 9 次课开发计划里找到了要记住的信息与再看的时刻。
  • SQLite Viewer를 설치했다.装好了 SQLite Viewer。
확인하지 않고 DB를 붙이면不确认就接数据库的话

현재 작동 상태를 확인하지 않고 DB를 추가하면 새 문제와 기존 문제를 구분하기 어렵습니다. 버튼이 안 되는 것이 저장 때문인지 원래부터였는지 알 수 없게 됩니다.不确认当前的运行状态就加数据库，就分不清新问题和原有问题。按钮不好用，到底是因为保存，还是本来就不行，会说不清。

4. 대조4. 对照11-2

AI의 제안을 계획서와 대조한다把 AI 的提议与计划书对照 핵심核心

  • 테이블의 역할이 후보 테이블과 맞는가?表的作用与候选数据表一致吗？
  • 저장할 정보가 핵심 기능에 필요한가?要保存的信息对核心功能必要吗？
  • 계획서에 없는 개인정보가 추가되지 않았는가?有没有加了计划书里没有的个人信息？
  • 불필요하게 복잡한 관계를 만들지 않았는가?有没有造出不必要的复杂关系？
  • 사용자가 남긴 정보와 저장할 값이 연결되는가?用户留下的信息与要保存的值对得上吗？
  • 사용자가 다시 보는 단계에서 필요한 정보가 나타나는가?在用户再次查看的那一步，需要的信息会出现吗？
  • 표준 DB 위치와 패키지를 유지하는가?是否保持了标准的数据库位置与包？
학생이 다시 설계하지 않습니다学生不重新设计

세부 열 · 자료형 · 키를 학생이 다시 설계하지 않습니다. 사용자의 기대와 맞지 않는 부분만 지적합니다.细节的列、数据类型、键，学生不重新设计。只指出与用户期待不符的地方。

5. 흐름 실행5. 跑流程11-2

기억하고 다시 보는 흐름을 실행한다跑一遍“记住并再看到”的流程 실습实践

여섯 단계六步
  1. AI가 제안한 변경 범위를 확인한다.确认 AI 提议的改动范围。
  2. 변경을 적용하고 프로젝트를 실행한다.应用改动并运行项目。
  3. 대표 흐름으로 정상 기록 한 개를 만든다.按代表流程造出一条正常记录。
  4. 화면에서 완료 반응을 확인한다.在画面上确认完成的反应。
  5. 사용자가 기록을 다시 보는 단계로 이동한다.走到用户再次查看记录的那一步。
  6. 같은 정보가 화면에 나타나는지 확인한다.确认同一份信息是否出现在画面上。
  • 사용자가 한 행동用户做的行动
  • 기억해야 할 정보该记住的信息
  • 다시 보는 단계再次查看的步骤
  • 화면에서 확인한 내용在画面上确认到的内容
6. DB 확인6. 查数据库11-2

SQLite Viewer로 실제 데이터를 확인한다用 SQLite Viewer 确认真实数据 실습实践

다섯 단계五步
  1. 프로젝트에서 표준 .db 파일을 찾는다.在项目里找到标准的 .db 文件。
  2. VS Code에서 파일을 클릭하여 SQLite Viewer로 연다.在 VS Code 里点开文件，用 SQLite Viewer 打开。
  3. 계획서와 관련된 테이블 이름을 찾는다.找到与计划书对应的表名。
  4. 화면에서 입력한 값이 행으로 보이는지 확인한다.确认在画面上输入的值是否显示为一行。
  5. 화면의 값과 DB의 값이 같은지 비교한다.比较画面上的值与数据库里的值是否相同。
  • DB 파일 위치数据库文件位置
  • 확인한 테이블查看的表
  • 행의 개수行数
  • 화면과 일치하는 값与画面一致的值
  • 불필요하게 저장된 값多余保存的值
Viewer에서 값을 고치지 않습니다不要在查看器里改值

SQLite Viewer에서 값을 직접 수정하거나 삭제하지 않습니다. 최신 값이 보이지 않으면 저장 동작을 마친 뒤 DB 화면을 다시 엽니다.在 SQLite Viewer 里不直接修改或删除值。若看不到最新的值，就在保存动作完成后重新打开数据库界面。

7. 재실행7. 重新运行11-2

프로젝트 재실행 뒤 사용자 경험을 확인한다重启项目后确认用户体验 실습实践

10-2에서 사라졌던 문제의 답10-2 里“消失了”那个问题的答案
  1. 프로젝트 실행을 완전히 중지한다.彻底停止项目的运行。
  2. 같은 방법으로 다시 실행한다.用同样的方法重新运行。
  3. 브라우저를 새로 연다.重新打开浏览器。
  4. 이전 기록이 다시 나타나는지 확인한다.确认之前的记录是否再次出现。
  5. SQLite Viewer에서 같은 행이 남아 있는지 확인한다.在 SQLite Viewer 里确认那一行是否还在。
사라지면 흐름에 맞지 않습니다消失了就与流程不符

기록이 사라지면 PRD와 9회의 사용자 흐름에 맞지 않습니다. 10절의 요청문으로 기억하기 · 다시 불러오기 · 화면에 보여 주기 중 어느 단계가 문제인지부터 좁힙니다.记录消失，就与 PRD 和第 9 次课的用户流程不符。用第 10 节的请求文，先在记住 · 取回 · 显示到画面三步里收窄问题出在哪一步。

여기까지 되면 11회 목표 달성입니다做到这里，第 11 次课的目标就达成了

껐다 켜도 기록이 남아 있고 사용자가 그것을 다시 볼 수 있다면, 대표 흐름과 데이터 기억 기능이 함께 작동하는 것입니다.关掉再开记录还在，用户也能再看到，就说明代表流程与数据记忆功能一起跑通了。

8. 단순함 점검8. 检查是否简单11-2

복잡하게 만들지 않았는지 확인한다确认有没有做复杂了 핵심核心

  • 핵심 기능과 관계없는 기록을 추가하지 않았다.没有加与核心功能无关的记录。
  • 한 테이블로 충분한데 여러 테이블로 나누지 않았다.一张表就够，没有拆成好几张。
  • 실제 개인정보와 불필요한 입력값을 저장하지 않았다.没有保存真实个人信息与多余的输入值。
  • 기록을 만드는 행동과 다시 보는 화면이 사용자 흐름에 포함된다.产生记录的行为与再次查看的画面，都包含在用户流程里。
  • 학생이 열 · 자료형 · 관계를 직접 설계하거나 외우지 않는다.学生没有亲自设计或背诵列、数据类型与关系。
두 번째 항목이 자주 걸립니다第二项最常出问题

AI는 표를 더 잘게 나누는 방향으로 답하기 쉽습니다. 그것이 더 전문적으로 보이기 때문입니다. 7-1에서 본 대로 나눌 이유가 없으면 하나가 정답입니다.AI 很容易往把表拆得更细的方向答，因为那看起来更专业。正如 7-1 所见，没有理由拆开时，一张就是正解。

- 서버가 안전한 새 파일명을 만들어 저장하기
- SQLite에는 파일 자체가 아니라 표시 이름·저장 경로·설명만 기록하기
- 실행 파일과 허용하지 않은 형식은 저장하지 않고 안내하기
- 원래 파일명으로 서버 경로를 직접 만들지 않기
- 파일 내용을 명령이나 코드로 실행하지 않기

구현 전에 저장 위치, DB에 기록할 정보와 거부할 입력을 설명해 줘.

확인할 내용要确认的内容

  • 허용한 작은 파일이 업로드되는가?允许的小文件能上传吗？
  • 허용하지 않은 형식은 거부되는가?不允许的格式会被拒绝吗？
  • 크기 제한을 넘으면 안내하는가?超过大小限制会给出提示吗？
  • 업로드된 파일이 SQLite 안이 아니라 별도 폴더에 있는가?上传的文件是在单独的文件夹而不是 SQLite 里吗？
  • DB에는 파일 정보만 기록되는가?数据库里只记了文件信息吗？
