「? 자리」는 왜 넣나요为什么要加“? 占位符”

사용자가 입력한 글자를 SQL 문장에 그대로 이어 붙이면, 이상한 입력 하나로 표가 망가지거나 남의 기록이 보일 수 있습니다. 값을 ? 자리로 따로 넘기면 데이터베이스가 그 값을 글자로만 다룹니다. 7-2에서 본 보안과 같은 이야기입니다.如果把用户输入的文字直接拼进 SQL 语句，一个奇怪的输入就可能弄坏表，或让别人的记录被看到。把值通过 ? 占位符单独交过去，数据库就只把它当文字处理。这和 7-2 讲的安全是同一回事。

4. 화면에서 확인4. 在画面上确认11-2

기록을 하나 남기고 다시 보는 자리에서 찾는다留下一条记录，在再次查看的位置找到它 실습实践

이제 첫 번째 확인입니다. 내 서비스를 실제로 쓰는 사용자처럼 의미 있는 값을 넣어 기록을 하나 남깁니다. 「test」나 「ㅁㄴㅇ」 같은 값은 나중에 SQLite Viewer에서 화면과 대 볼 때 구별하기 어렵습니다. 결과를 본 뒤에는 그 기록이 다시 보이는 자리까지 따라갑니다.现在是第一次确认。像真正使用这个服务的用户那样，输入有意义的值，留下一条记录。“test”或乱打的字，之后在 SQLite Viewer 里和画面对照时很难分辨。看到结果后，一直跟到这条记录再次显示的位置。

순서顺序
  1. 브라우저에서 F5로 새로고침해 바뀐 화면을 연다.在浏览器里按 F5 刷新，打开改过的画面。
  2. 핵심 행동을 바르게 한 번 한다. 완료 반응(결과 · 안내)을 확인한다.正确地做一次核心动作。确认完成后的反应（结果 · 提示）。
  3. 내 흐름에서 기록을 다시 보는 자리(목록 · 최근 기록 등)에 방금 값이 나타나는지 본다.看刚才的值有没有出现在我的流程里再次查看记录的位置（列表 · 最近记录等）。
  4. F5로 새로고침한다. 11-1 처음과 달리 기록이 그대로 있는지 본다.按 F5 刷新。看记录是不是和 11-1 开头不同，还在原处。
  5. 입력을 비우거나 잘못 넣고 한 번 더 누른다. 안내만 나오고 기록은 늘지 않아야 한다.把输入留空或输错，再按一次。应该只出现提示，记录不增加。

저장은 됐는데 다시 보여 주는 화면을 만들지 않은 것입니다. 바로 5절로 가서 SQLite Viewer에 행이 있는지 먼저 확인하고, 7절의 요청문으로 「다시 불러오기」를 붙입니다.这说明保存了，但没有做重新显示的画面。直接去第 5 节，先在 SQLite Viewer 里确认有没有行，再用第 7 节的请求接上“重新读取”。

5. Viewer에서 확인5. 在 Viewer 里确认11-2

SQLite Viewer에서 같은 값의 행을 찾는다在 SQLite Viewer 里找到同样值的行 실습实践

두 번째 확인은 파일 쪽입니다. 처음 저장하는 순간 data 폴더 안에 app.db가 생겼을 것입니다. 이 파일을 SQLite Viewer로 열어, 화면에서 남긴 값이 정말 한 행으로 적혔는지 봅니다. 화면과 Viewer를 나란히 놓고 한 줄씩 대 보면 빠릅니다.第二次确认是在文件这边。第一次保存的那一刻，data 文件夹里应该出现了 app.db。用 SQLite Viewer 打开这个文件，看画面上留下的值是不是真的写成了一行。把画面和 Viewer 并排放着一行一行对照，会很快。

순서顺序
  1. VS Code 탐색기에서 data 폴더를 펼치고 app.db를 누른다. SQLite Viewer로 열린다.在 VS Code 资源管理器里展开 data 文件夹，点 app.db。它会用 SQLite Viewer 打开。
  2. 왼쪽에서 11-1 계획에 나온 표 이름을 누른다.在左边点 11-1 计划里说到的表名。
  3. 방금 화면에서 남긴 값이 행으로 있는지, 행의 개수가 남긴 횟수와 같은지 본다.看刚才在画面上留下的值有没有成为一行，行数和留下的次数是否一样。
  4. Win+← · Win+→로 브라우저와 VS Code를 나란히 놓고 값을 한 줄씩 대 본다.用 Win+← · Win+→ 把浏览器和 VS Code 并排，逐行对照值。
Viewer에서는 고치지도 지우지도 않습니다在 Viewer 里不改也不删

틀린 행이 보여도 Viewer에서 직접 고치지 않습니다. 기록은 언제나 내 서비스의 화면에서 만들고, 고칠 것은 7절처럼 AI에게 말합니다. 새 행이 안 보이면 Viewer 탭을 닫고 app.db를 다시 엽니다.就算看到不对的行，也不要在 Viewer 里直接改。记录永远在自己服务的画面上产生，要改的地方像第 7 节那样告诉 AI。看不到新行时，关掉 Viewer 标签页，再重新打开 app.db。

6. 다시 켜기6. 重新启动11-2

서버를 껐다 켜도 기록이 남는지 본다看看关掉服务器再打开，记录还在不在 실습实践

세 번째 확인이 11-1 첫 장면의 답입니다. 새로고침은 화면만 다시 그리지만, Ctrl+C로 서버를 멈추면 실행 중에 들고 있던 것이 모두 사라집니다. 그런데도 기록이 남아 있다면 그 기록은 파일에서 다시 읽어 온 것입니다.第三次确认就是 11-1 第一个场景的答案。刷新只是把画面重画一遍，而用 Ctrl+C 停掉服务器，运行中拿着的东西会全部消失。即使这样记录还在，就说明它是从文件里重新读回来的。

순서顺序
  1. npm run dev 터미널을 누르고 Ctrl+C를 누른다. 「일괄 작업을 끝내시겠습니까 (Y/N)?」가 보이면 Y와 Enter.点 npm run dev 终端，按 Ctrl+C。如果出现“일괄 작업을 끝내시겠습니까 (Y/N)?”（要终止批处理操作吗），就按 Y 和 Enter。
  2. 줄 끝에 …\10>가 다시 보이면 서버가 멈춘 것이다. 브라우저를 새로고침하면 연결할 수 없다는 화면이 나온다.行末重新出现 …\10>，说明服务器停了。这时刷新浏览器，会出现无法连接的画面。
  3. npm run dev를 다시 입력하고 Ready를 기다린다.重新输入 npm run dev，等出现 Ready。
  4. 브라우저 탭을 닫고 새 탭에서 http://localhost:3000을 연다. 다시 보는 자리에 기록이 그대로 있는지 본다.关掉浏览器标签页，在新标签页打开 http://localhost:3000。看再次查看的位置，记录是否原样还在。
  5. SQLite Viewer 탭을 닫았다가 app.db를 다시 열어 같은 행이 남았는지 본다.关掉 SQLite Viewer 标签页，再重新打开 app.db，看同样的行是否还在。
여기까지 되면 11회의 목표에 닿았습니다做到这里，就达到第 11 次课的目标了

다시 켜도 기록이 남고 사용자가 그것을 다시 볼 수 있습니다. 10회에 만든 요청과 응답 위에 기억이 붙은 것입니다. 12회에는 이 흐름 전체를 사용자처럼 시험합니다.重新启动后记录还在，用户也能再次看到它。这就是在第 10 次课做的请求和响应之上，接上了记忆。第 12 次课会像用户那样测试整个流程。

11. 정리11. 小结11-2

내 서비스가 다시 켜도 기억한다我的服务重新打开也能记住了

오늘은 11-1에서 들은 계획에 「진행해」를 보내 저장과 다시 불러오기를 연결했습니다. 화면, SQLite Viewer, 다시 켠 뒤 세 번 확인했고, 어긋나면 세 단계 중 처음 끊긴 곳만 고쳤습니다. 이 프로젝트는 12회에도 같은 10 폴더에서 이어 갑니다.今天对 11-1 听到的计划发送了“진행해”（开始做），把保存和重新读取连接起来了。在画面、SQLite Viewer、重新启动后确认了三次，出错时只修三步中最先断开的地方。这个项目第 12 次课也在同一个 10 文件夹里继续。

이번 차시에서 남길 것本课时要记住的
  • 고치기 전에 계획을 듣고, 맞으면 「진행해」로 고치게 한다.改之前先听计划，对了再用“진행해”（开始做）让它改。
  • 기억했는지는 화면 · SQLite Viewer · 다시 켠 뒤 세 번 확인한다.是否记住了，要在画面 · SQLite Viewer · 重新启动后确认三次。
  • 어긋나면 저장하기 · 다시 불러오기 · 화면에 보여 주기 중 처음 끊긴 한 단계만 가장 작게 고친다.出错时，只在保存 · 重新读取 · 显示到画面中，把最先断开的那一步做最小的修改。

저장을 붙이다 보면 막히는 자리가 비슷하게 나옵니다. 내 상황과 같은 줄을 찾아 오른쪽대로 해 봅니다. 그래도 안 되면 터미널의 빨간 글자 첫 줄을 지우지 말고 그대로 둔 채 손을 듭니다.接保存时，卡住的地方大多相似。找到和自己情况一样的那行，照右边做。还不行就别清掉终端里红字的第一行，保留着举手。

이런 상황이라면如果是这些情况
data 폴더에 app.db가 없다data 文件夹里没有 app.db파일은 처음 저장하는 순간 생깁니다. 화면에서 기록을 하나 남긴 뒤 탐색기 위쪽의 새로 고침 단추를 누릅니다. 그래도 없으면 저장하기 단계를 7절처럼 묻습니다.文件是在第一次保存的那一刻出现的。在画面上留下一条记录后，点资源管理器上方的刷新按钮。还是没有的话，就像第 7 节那样问保存这一步。
app.db를 눌렀더니 깨진 글자가 보인다点 app.db 后看到乱码SQLite Viewer가 아니라 기본 편집기로 열린 것입니다. 아무것도 고치지 말고 탭을 닫습니다. 확장 화면에서 SQLite Viewer에 제거 단추가 보이는지(설치되었는지) 확인한 뒤 app.db를 다시 누릅니다.这是没用 SQLite Viewer，而是用默认编辑器打开了。什么都别改，关掉标签页。在扩展画面确认 SQLite Viewer 上显示 제거（卸载）按钮（即已安装），再重新点 app.db。
터미널에 no such table이나 has no column named가 나온다终端出现 no such table 或 has no column namedAI가 표 모양을 바꿨는데 app.db에는 예전 표가 남아 있는 경우가 많습니다. 빨간 글자 첫 줄을 7절 요청문의 「화면에 보인 것」에 붙여 보냅니다. app.db를 지우는 것은 손을 들어 확인받은 뒤에만 합니다.多半是 AI 改了表的样子，而 app.db 里还留着以前的表。把红字的第一行贴到第 7 节请求的“画面上看到的”里发送。删除 app.db 要先举手确认后才做。
AI가 npm install로 새 패키지를 설치하려 한다AI 想用 npm install 安装新包허락하지 않습니다. 「새 패키지는 쓰지 않아. Node에 들어 있는 node:sqlite와 lib/db.js의 getDb()만 써 줘」를 보냅니다.不要同意。发“不用新包。只用 Node 自带的 node:sqlite 和 lib/db.js 的 getDb()”。
FreeUsageLimitError나 429가 나온다出现 FreeUsageLimitError 或 4291~2분 기다렸다가 같은 요청을 다시 보냅니다. 그동안 SQLite Viewer에서 행을 화면과 대 봅니다.等 1~2 分钟再发同样的请求。这段时间在 SQLite Viewer 里把行和画面对照一下。
