들어가며开始之前9-1

문을 열었는데 아무 말이 없다推开门，却没人告诉你该怎么走

8회에 낸 PRD에는 서비스가 할 일이 적혀 있습니다. 오늘은 그 서비스를 처음 쓰는 사람의 걸음으로 다시 읽습니다. 기능이 다 있어도 사용자가 어디서 시작해 어디로 가야 하는지 모르면 서비스는 쓰이지 않습니다. 먼저 이런 장면을 떠올려 봅니다.第 8 次课交的 PRD 里写着服务要做的事。今天要用第一次使用的人的脚步重新读它。就算功能都有，如果用户不知道从哪里开始、往哪里走，服务也不会被用起来。先想象一下这样的场景。

이런 장면这样的场景

처음 가 보는 관공서에 들어갔습니다. 안내 데스크도, 번호표 기계도, 안내문도 보이지 않습니다. 창구가 다섯 개 있는데 어디로 가야 하는지 알 수 없습니다.你走进一个第一次去的办事大厅。没有咨询台，没有取号机，也没有指示牌。窗口有五个，可你不知道该去哪一个。

이 건물에 기능이 없는 것이 아닙니다. 창구도 있고 직원도 있습니다. 없는 것은 사용자가 처음부터 끝까지 지나갈 길입니다.这栋楼不是没有功能。窗口有，工作人员也有。缺的是让人从头走到尾的那条路。

핵심 질문核心问题

사용자가 이 서비스를 처음 열었을 때부터 원하는 결과를 얻을 때까지
어떤 일을 차례대로 겪게 될까?用户从第一次打开这个服务，到拿到想要的结果，
会依次经历些什么？

2. 사용자 흐름2. 用户流程9-1

사용자 흐름은 사용자가 지나가는 길이다用户流程是用户走过的路 핵심核心

PRD의 2항은 서비스가 할 수 있는 일을, 4항은 화면에 무엇이 있는지를 적었습니다. 둘 다 순서가 없습니다. 사용자 흐름은 여기에 순서를 붙입니다. 사용자가 처음 화면을 본 순간부터 목적을 이룰 때까지 차례대로 무엇을 겪는지 적는 것입니다.PRD 第 2 项写的是服务能做的事，第 4 项写的是画面上有什么。两者都没有顺序。用户流程就是给它们加上顺序：按先后写下用户从第一次看到画面，到达成目的为止，依次经历了什么。

사용자 흐름user flow用户流程user flow
현상现象
지하철역에는 개찰구, 계단, 승강장이 다 있습니다. 그런데 처음 온 사람이 헤매지 않는 역과 헤매는 역이 있습니다. 시설의 개수가 아니라 지나가는 순서가 안내되어 있는가의 차이입니다.地铁站里检票口、楼梯、站台都有。可有的站第一次来的人不会迷路，有的站会。差别不在设施数量，而在有没有把要走的顺序指出来。
쉬운 설명通俗说法
사용자가 서비스를 처음 열어 목적을 이룰 때까지 지나가는 길입니다.用户从打开服务到达成目的所走的那条路。
정확한 정의准确定义
사용자가 목적을 이루기까지 거치는 단계를, 각 단계에서 보는 것 · 하는 행동 · 서비스의 반응으로 이어 붙인 것.把用户达成目的所经过的各个步骤，按每一步的看到什么 · 做什么 · 服务如何回应串起来。
경계边界
기능 목록과 화면 목록은 순서가 없습니다. 흐름에는 순서가 있습니다.功能清单和画面清单没有顺序。流程有顺序。
문장 속 사용句中用法
“이 사용자 흐름은 할 일을 입력하는 데서 시작해, 다시 열어 남은 기록을 보는 데서 끝난다.”“这个用户流程从输入待办事项开始，到重新打开后看到留下的记录结束。”
2. 사용자 흐름2. 用户流程9-1

사용자 흐름과 개발 순서는 다르다用户流程与开发顺序不一样

흐름을 정하지 않고 바로 개발 계획을 세우면 「무엇부터 만들까」에 마음이 먼저 갑니다. 그러면 만들기 쉬운 것부터 만들고, 정작 사용자가 목적을 이루는 길은 마지막까지 비어 있게 됩니다. 그래서 9회에는 사용자 흐름을 먼저 정하고, 개발 순서는 9-2 마지막에 만듭니다.如果不先定流程就直接做开发计划，心思会先跑到“先做什么”上。结果就是先做容易做的，而用户达成目的的那条路到最后还是空的。所以第 9 次课先定用户流程，开发顺序放到 9-2 最后再做。

사용자 흐름 · 사용자가 겪는 순서用户流程 · 用户经历的顺序
  • 서비스를 열고 안내를 본다打开服务，看到说明
  • 값을 입력하거나 고른다输入或选择
  • 버튼을 누른다按下按钮
  • 결과를 확인한다确认结果
  • 기록이 남는다留下记录
  • 다시 열어 기록을 본다重新打开，查看记录
개발 순서 · 만드는 사람이 일하는 순서开发顺序 · 做的人工作的顺序
  • 첫 화면을 만든다做出第一个画面
  • 핵심 기능을 작동시킨다让核心功能跑起来
  • 기록 저장과 다시 보기를 연결한다接上记录的保存与再次查看
  • 테스트하고 고친다测试并修改
주인공이 다릅니다主角不一样

왼쪽의 주인공은 사용자이고 오른쪽의 주인공은 만드는 사람입니다. 오늘 쓰는 것은 왼쪽입니다.左边的主角是用户，右边的主角是做的人。今天写的是左边。

3. 시작과 완료3. 开始与完成9-1

흐름의 시작과 완료를 먼저 한 줄씩 정한다先用一句话分别定下流程的开始与完成 핵심核心

흐름을 쓸 때는 가운데 단계보다 시작과 완료를 먼저 정합니다. 시작은 사용자가 서비스를 처음 열었을 때 보는 것이고, 완료는 사용자가 목적을 이뤘다고 느끼는 순간입니다. 이 두 줄이 정해져야 그 사이를 채울 수 있습니다.写流程时，先定开始与完成，再写中间的步骤。开始是用户第一次打开服务时看到的东西，完成是用户觉得目的达成的那一刻。这两句定下来，中间才填得进去。

09_user_flow.md · 1. 시작과 완료의 틀09_user_flow.md · “1. 시작과 완료”（开始与完成）的格式
- 시작: 사용자가 서비스를 처음 열고 ___을 본다.
- 완료: 사용자가 ___을 하고 ___ 결과와 저장된 기록을 확인한다.
- 시작（开始）: 用户第一次打开服务，看到 ___。
- 완료（完成）: 用户做了 ___，确认 ___ 结果和已保存的记录。
채워 넣은 예 — 할 일 정리 서비스填好的例子 — 待办整理服务
- 시작: 사용자가 할 일 정리 서비스를 열고 입력 안내를 본다.
- 완료: 사용자가 할 일을 추가하고, 다시 열어도 목록에 남은 기록을 확인한다.
- 시작（开始）: 用户打开待办整理服务，看到输入说明。
- 완료（完成）: 用户添加待办事项，重新打开后也能在列表里看到留下的记录。
완료 문장에 「다시 보는 순간」이 들어갑니다完成那句里要有“再次查看的时刻”

예의 완료 문장에는 「다시 열어도 목록에 남은」이 있습니다. 7-2에서 정한 기록을 다시 확인하는 순간입니다. 결과를 한 번 보여 주고 끝나면 아직 완료가 아닙니다.例子的完成那句里有“重新打开后也能在列表里看到”。这就是 7-2 定下的再次查看记录的时刻。只把结果显示一次就结束，还不算完成。

4. 한 단계4. 一个步骤9-1

한 단계에는 다섯 가지를 적는다一个步骤写五样东西 핵심核心

시작과 완료 사이를 단계로 나눕니다. 한 단계마다 아래 다섯 가지를 적으면, 사용자가 무엇을 보고 하는지와 서비스가 무엇을 돌려주는지가 빠짐없이 드러납니다. 네 번째 칸은 11회에 SQLite에 저장할 기록의 재료가 되고, 다섯 번째 칸은 12회 테스트에서 그대로 시험합니다.把开始与完成之间分成几步。每一步都写下面五样，用户看到什么、做什么，服务回给什么，就都不会漏。第四格是第 11 次课存进 SQLite 的记录的材料，第五格会在第 12 次课测试时照着试。

칸格확인할 질문要问的问题
사용자가 보는 것用户看到的이 단계에서 화면에 무엇이 보이는가?这一步画面上能看到什么？
사용자의 행동用户的动作무엇을 입력하거나 고르거나 누르는가?输入、选择或按下什么？
서비스의 반응服务的回应행동 뒤에 화면에서 무엇이 바뀌거나 나타나는가?动作之后画面上什么变了、出现了什么？

5. 정상과 예외5. 正常与例外9-1

정상 흐름 하나, 예외 흐름 하나부터 정한다先定一条正常流程、一条例外流程 핵심核心

  • 추가를 누른다按添加
  • 목록에서 확인한다在列表里确认

6. 목록과 흐름6. 清单与流程9-1

화면 이름만 적으면 흐름이 아니다只写画面名称不算流程 핵심核心

흐름을 쓰다 보면 화면 이름만 늘어놓기 쉽습니다. 그러면 사용자가 무엇을 하고 서비스가 어떻게 반응하는지 알 수 없습니다. 각 줄을 읽고 「누가 무엇을 했는가?」를 물어 답이 나오면 흐름이고, 답이 안 나오면 목록입니다.写流程时很容易只把画面名称排一排。那样就看不出用户做了什么、服务怎么回应。读每一行时问“谁做了什么？”，答得出来就是流程，答不出来就是清单。

이것은 화면 목록这是画面清单
  • 메인 화면主画面
  • 입력 화면输入画面
  • 결과 화면结果画面
이것이 흐름这才是流程
  • 메인 화면에서 설명을 확인한다在主画面确认说明
  • 값을 입력하고 실행을 누른다输入值，按执行
  • 서비스가 입력을 확인한다服务检查输入
  • 결과 또는 고칠 곳을 보여 준다显示结果，或显示要改的地方
「누가 무엇을 했는가?」“谁做了什么？”

「메인 화면」에는 답할 수 없지만 「설명을 확인한다」에는 답할 수 있습니다. 사용자가 했습니다. 오늘 쓰는 흐름의 모든 줄이 이 질문에 답해야 합니다.“主画面”回答不了，“确认说明”回答得了：是用户做的。今天写的流程，每一行都要答得出这个问题。

10. 오해10. 误解9-1

흔한 오해와 사실常见误解与事实

흐름을 처음 쓸 때 자주 하는 생각이 세 가지 있습니다. 내 흐름을 다시 보면서 같은 생각을 하지 않았는지 확인합니다. 특히 마지막 오해는 10회부터 AI와 개발할 때 그대로 문제가 됩니다.第一次写流程时，常有三种想法。回头看自己的流程，确认有没有这样想。尤其是最后一个误解，从第 10 次课和 AI 一起开发时就会直接变成问题。

오해误解
“흐름은 화면이 여러 개일 때만 필요하다.”“只有画面有好几个时才需要流程。”
사실事实
화면이 하나여도 흐름은 있습니다. 할 일 정리의 네 단계는 모두 같은 화면에서 일어납니다. 흐름을 만드는 것은 행동과 반응의 변화입니다.哪怕只有一个画面，流程也存在。待办整理的四步都在同一个画面里。构成流程的是动作与回应的变化。
오해误解
“예외 상황을 많이 적을수록 꼼꼼한 설계다.”“例外情况写得越多，设计越细致。”
사실事实
지금은 핵심 행동을 막는 예외 하나면 충분합니다. 나머지는 12회 테스트에서 찾아 고칩니다.现在一条挡住核心动作的例外就够了。其余的到第 12 次课测试时再找、再改。
오해误解
“어차피 AI가 만들 테니 흐름은 대충 적어도 된다.”“反正 AI 会做，流程随便写写就行。”
사실事实
AI는 적힌 대로 만듭니다. 흐름이 비어 있으면 AI가 자기 생각으로 채우고, 그 결과가 내 서비스와 달라도 알아채기 어렵습니다.AI 照着写的去做。流程空着，AI 就会按自己的想法去填，结果和自己的服务不一样也很难发现。
11. 확인11. 确认9-1

확인 문제确认题 확인确认

오늘 배운 것을 세 문제로 확인합니다. 답을 먼저 말해 보고 해설을 엽니다. 답이 막히는 문제가 있으면 그 절로 돌아가 다시 읽습니다. 해설은 인쇄하면 펼쳐진 채로 나옵니다.用三道题确认今天学的内容。先说出答案，再打开解析。答不上来的题，就回到那一节再读一遍。打印时解析会是展开的。

사용자 흐름과 개발 순서의 차이는 무엇인가?用户流程与开发顺序有什么不同？
해설 보기查看解析

주인공이 다릅니다. 사용자 흐름은 사용자가 겪는 순서이고, 개발 순서는 만드는 사람이 일하는 순서입니다. 사용자 흐름을 먼저 정하고 개발 순서는 그 뒤에 만듭니다.主角不同。用户流程是用户经历的顺序，开发顺序是做的人工作的顺序。先定用户流程，开发顺序在那之后再做。

「메인 화면 → 입력 화면 → 결과 화면」이 흐름이 아닌 이유는?为什么“主画面 → 输入画面 → 结果画面”不算流程？
해설 보기查看解析

행동과 반응이 빠져 있기 때문입니다. 각 줄에 「누가 무엇을 했는가?」를 물으면 답이 나오지 않습니다.因为缺了动作与回应。对每一行问“谁做了什么？”，答不出来。

흐름에 외부 AI가 꼭 필요한 기능이 있다면 개발 전에 무엇을 하는가?如果流程里有离不开外部 AI 的功能，开发前要做什么？
해설 보기查看解析

사용자가 그 기능으로 얻으려던 결과를 적고, 00_course_rules.md를 보며 규칙이나 예시 자료로 같은 결과를 낼 수 있는지 찾습니다. 숨기고 시작하지 않습니다.写下用户想通过这个功能得到的结果，对照 00_course_rules.md，找找能不能用规则或示例资料得到同样的结果。不要藏着开工。

12. 정리12. 小结9-1

내 서비스의 길이 한 장에 적혔다自己服务的那条路写在了一页上

오늘은 PRD의 대표 사용 흐름을 펼쳐, 사용자가 보는 것·행동·서비스의 반응·남는 정보로 09_user_flow.md에 적었습니다. 예외 흐름 하나와 확인이 필요한 기능도 적었습니다. 이 파일은 다음 차시에 AI가 읽을 자료이니 09 폴더에 그대로 둡니다.今天把 PRD 的代表性使用流程展开，按看到的、动作、服务的回应、留下的信息写进了 09_user_flow.md。还写了一条例外流程和需要确认的功能。这个文件是下一课时 AI 要读的资料，原样放在 09 文件夹里。

이번 차시에서 남길 것本课时要记住的
  • 사용자 흐름은 사용자가 겪는 순서이고, 개발 순서보다 먼저 정한다.用户流程是用户经历的顺序，要比开发顺序先定。
  • 한 단계에는 보는 것 · 행동 · 반응 · 남는 정보 · 예외를 적는다.一个步骤写看到的 · 动作 · 回应 · 留下的信息 · 例外。
  • 완료에는 기록을 다시 보는 순간이 들어간다.完成里要有再次查看记录的时刻。
  • 만들기 어려운 기능은 숨기지 않고, 사용자가 얻으려던 결과와 함께 적는다.难做的功能不藏起来，和用户想得到的结果一起写下来。
