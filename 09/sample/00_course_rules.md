# 수업 개발 조건 — 수업에서 만들 수 있는 것과 어려운 것

이 파일은 9~13회에 AI가 PRD.md보다 먼저 읽는 수업 조건이다.
AI는 학생의 아이디어를 바로 코드로 만들지 않고, 먼저 이 조건 안에서 가능한지 확인한다.

## 1. 수업 프로젝트의 기본 조건

- 만드는 사람은 웹서비스를 처음 만드는 중·고등학생이다.
- 학생은 코드를 처음부터 쓰지 않는다. AI가 만든 결과를 실행하고, 확인하고, 고쳐 달라고 요청한다.
- 9회에는 코드·화면·프로젝트 파일을 만들거나 고치지 않는다. 실제 개발은 10회부터다.
- 10회부터는 선생님이 나눠 주는 표준 프로젝트(Next.js) 하나에서 만든다.
- 화면과 서버를 다른 프로젝트로 나누지 않는다.
- 패키지·프레임워크·포트·DB 위치·공개 방법은 학생이 고르지 않는다. 표준 프로젝트에 정해져 있다.
- 핵심 기능은 한 가지다.
- 모든 서비스는 핵심 기능을 쓰면 생기는 의미 있는 기록을 하나 이상 SQLite에 저장하고, 다시 보여 준다.
- 표는 한 개로 시작해도 된다. 표 수를 늘리려고 쓸모없는 기록을 만들지 않는다.
- 실제 개인정보와 민감한 정보를 쓰지 않는다.

## 2. 수업에서 쓸 수 있는 기능

- 글자·숫자·날짜 입력
- 항목 고르기와 버튼 누르기
- 입력 확인, 간단한 계산·분류·정렬·검색
- 결과·안내·목록 보여 주기
- SQLite에 핵심 기록 저장하고 다시 불러오기
- 선생님이 준비한 이미지와 예시 자료(CSV·JSON)
- 브라우저 화면 안의 간단한 2D 그림과 움직임
- 새로고침하거나 다시 켠 뒤 결과 확인

## 3. 이번 수업에서 만들지 않는 기능

- ChatGPT·Gemini 같은 외부 AI 서비스 연결과 API 키
- 유료 서비스
- Firebase·Supabase 같은 외부 DB와 클라우드 저장
- Google·Kakao 로그인, 회원가입, 비밀번호, 여러 기기 동기화
- 이메일·문자·푸시 알림
- 결제·광고
- 다른 웹사이트의 내용을 긁어 오기(크롤링), 영상·음성 분석
- 실시간 채팅, 여러 사람이 동시에 하는 게임
- 휴대폰 잠금화면·홈 화면 위젯 같은 앱 기능
- 선생님이 허락하지 않은 새 패키지
- 학생 계정으로 인터넷에 공개하기

## 4. 선생님 확인을 받아야 하는 기능

- 파일 올리기(업로드)와 파일 저장
- 외부 공개 자료 연결
- 핵심 기능에 꼭 필요한 추가 패키지(예: 3D 그림 도구)
- 외부 사이트의 지도·영상 연결

AI는 위 기능을 개발 계획에 넣지 말고 `교사 확인 필요`라고만 표시한다.
학생과 선생님이 확인하기 전에는 그 기능이 있다고 가정하고 계획을 세우지 않는다.

## 5. 어려운 기능을 만났을 때

어려운 기능을 몰래 다른 기능으로 바꾸거나, 작동하지 않는 기능을 된 것처럼 말하지 않는다.
먼저 사용자가 그 기능으로 얻으려던 결과를 말하고, 수업에서 만들 수 있는 작은 대안을 제안한다.

| 원래 아이디어 | 수업에서 만들 수 있는 대안 |
|---|---|
| AI가 글이나 질문을 이해해 답한다 | 학생이 정한 규칙·키워드로 답을 고른다, 또는 준비한 예시 답을 보여 준다 |
| AI가 사진·영상·소리를 분석한다 | 사용자가 필요한 값(단어, 코드, 숫자)을 직접 입력한다 |
| 로그인해서 내 기록을 본다 | 로그인 없이 한 기기에서 쓴다. 필요하면 이름(별명)만 입력한다 |
| 여러 기기에서 이어서 쓴다 | 한 기기에서 다시 켜도 기록이 남는 것까지만 한다 |
| 알림·위젯으로 알려 준다 | 서비스 첫 화면에 오늘 할 일·상태를 보여 준다 |
| 친구와 실시간으로 대화·대결한다 | 한 화면에서 차례로 하거나, 남긴 기록을 목록으로 본다 |
| 3D 게임 | 브라우저 2D 화면에서 핵심 규칙 하나만 만든다. 판이 끝나면 기록을 남긴다 |
| 외부 지도 | 장소 목록과 주소 글자, 또는 선생님이 준비한 자료 |

AI 기능을 규칙이나 예시 자료로 바꿨다면 진짜 AI 기능이라고 설명하지 않고 `수업용 프로토타입`이라고 적는다.

## 6. 판정하는 방법

사용자 흐름의 기능마다 다음 넷 중 하나로 판정하고, 이유를 쉬운 말로 적는다.

1. **수업에서 구현 가능** — 표준 프로젝트 안에서 바로 만들 수 있다.
2. **단순화하면 구현 가능** — 목적은 남기고 범위를 줄여야 한다.
3. **교사 확인 필요** — 파일 올리기·외부 자료·추가 패키지가 필요하다.
4. **수업 범위에서 구현 어려움** — 외부 계정·유료 키·복잡한 운영이 필요하다.

판정한 뒤에도 학생이 확인하기 전에는 코드를 만들지 않는다.

## AI가 지킬 순서

사용자 흐름을 먼저 이해한다 → 각 단계가 이 조건 안에서 가능한지 확인한다 → 필요한 범위 조정을 제안한다 → 학생이 흐름과 범위를 확정한 뒤에만 개발 순서를 쓴다. 9회에는 코드를 만들거나 고치지 않는다.
