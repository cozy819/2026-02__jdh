오늘 확인하는 것今天要确认的

오늘 확인하는 것은 코드가 얼마나 훌륭한가가 아닙니다. 내가 무엇을 정했고, 무엇을 확인했고, 무엇을 판단했는가입니다.今天要看的不是代码有多漂亮，而是我定了什么、确认了什么、判断了什么。

AI가 코드를 많이 만들었다는 사실은 문제가 아닙니다. 그 결과를 내가 확인했는지가 문제입니다. 그래서 1회부터 계속 “확인하는 사람이 되자”고 말해 왔습니다.AI 写了很多代码，这本身不是问题。问题是那个结果我确认过没有。所以从第 1 次课起就一直在说：做那个去确认的人。

근거는 이미 문서에 있습니다依据都在文档里了

오늘 설명할 내용은 대부분 PRD · 개발 계획 · 테스트 기록에 이미 적혀 있습니다. 새로 만들어 낼 것이 아니라, 찾아서 말하는 것입니다.今天要说的内容，多半已经写在 PRD、开发计划与测试记录里了。不是现编，而是翻出来讲。

2. 실행2. 运行13-2

대표 사용자 흐름을 실행한다跑一遍代表性用户流程 실습实践

실행 순서执行顺序
  1. 플랫폼 미리보기 또는 로컬에서 첫 화면을 연다.在平台预览或本地打开首屏。
  2. 서비스의 사용자와 목적을 확인한다.确认服务的用户与目的。
  3. 처음 방문한 사용자처럼 시작 방법을 확인한다.像第一次来的用户那样确认怎么开始。
  4. 9회에 정한 대표 행동을 순서대로 실행한다.按第 9 次课定的代表行动依次执行。
  5. 핵심 결과가 PRD의 완성 기준과 맞는지 확인한다.确认核心结果是否符合 PRD 的完成标准。
  6. 핵심 예외 상황 뒤 다시 시도할 수 있는지 확인한다.确认核心例外之后能否重试。
  7. 다시 방문해 SQLite에 저장된 기록이 남는지 확인한다.再访问一次，确认 SQLite 里保存的记录还在。
지금 발견한 문제는 고치지 않습니다此刻发现的问题不修

새로운 문제가 발견되어도 기능을 새로 추가하지 않습니다. 발견한 것은 말로 설명하면 됩니다. “여기서 이런 문제가 남아 있고, 이유는 이렇습니다”라고 설명하는 것도 확인한 결과입니다.就算发现新问题，也不加新功能。发现了就用话说明。“这里还留着这个问题，原因是这样”——把这个讲出来，同样是确认过的结果。

실행이 불가능한 제출 오류는 교사의 안내에 따라 처리합니다.导致完全跑不起来的提交错误，按老师的指示处理。

줄인 것도 성과입니다缩减也是成果

줄이거나 바꾼 부분을 설명하는 것은 감점이 아닙니다. 9회에 배운 대로 범위를 조정하는 것도 판단입니다. 이유를 말할 수 있으면 됩니다.说明缩减或改动的部分不是扣分。像第 9 次课学的那样，调整范围本身就是一种判断。能说出理由就行。

4. 연결 설명4. 说明连接13-2

사용자 행동이 API와 DB로 이어지는 방식을 설명한다说明用户行动如何连到 API 与 DB 핵심核心

빈칸을 채워 말해 보기填空后说出来
화면에서 사용자는 ___을 보고 ___을 한다.
화면은 API에 ___ 데이터를 요청으로 보낸다.
API는 ___을 처리하고 ___ 응답을 돌려준다.
SQLite에는 ___ 기록이 저장된다.
사용자는 저장된 기록을 ___에서 다시 확인한다.
파일 이름과 문법을 설명하지 않습니다不必讲文件名与语法

파일 이름과 코드 문법을 설명하기보다, 자신의 서비스에서 사용자 행동 → API 요청·응답 → SQLite 저장·조회 → 화면 표시가 어떻게 이어지는지 말합니다.与其讲文件名和代码语法，不如说明自己的服务中用户行动 → API 请求·响应 → SQLite 保存·查询 → 画面显示如何连起来。

“route.ts에서 POST를 받아서…”보다 “버튼을 누르면 입력한 내용이 API에 전달되고, SQLite에 저장된 후 목록에 나타납니다”가 더 적절한 설명입니다.比起“在 route.ts 里接 POST……”，“按下按钮后，输入内容发送到 API，存入 SQLite 后显示在列表中”更合适。

10~11회에서 배운 것입니다这是第 10~11 次课学过的

10회에 만든 화면 ↔ API 연결에 11회의 SQLite 저장·조회를 덧붙인 과정입니다. 새로 공부할 것이 아닙니다.这是在第 10 次课的画面 ↔ API连接上加入第 11 次课的 SQLite 保存·查询。不是新内容。

모든 학생이 설명하는 것每位学生都要说的

모든 학생은 다시 방문하거나 프로젝트를 재실행한 뒤 저장된 기록을 확인한 결과를 설명합니다. 프로젝트 주제와 상관없이 공통입니다.每位学生都要说明再次访问或重启项目后，确认已保存记录的结果。不论项目主题，这是共通的。

6. AI와 나6. AI 与我13-2

AI와 학생의 역할을 구분한다区分 AI 与学生的角色 핵심核心

AI가 한 일AI 做的학생이 한 일学生做的
구현한 화면 또는 기능实现的画面或功能정한 사용자·목적·사용자 흐름定下的用户、目的、用户流程
제안한 DB 구조提议的数据库结构구현 가능성을 확인하고 범위를 조정한 내용确认可行性并调整范围的内容

확인하지 못한 부분을 말하는 것도 능력입니다. 모른다고 말할 수 있는 사람이 아는 것과 모르는 것을 구분하는 사람입니다.说出自己没能确认的部分，同样是一种能力。说得出“不知道”的人，才是分得清知道与不知道的人。

코드의 양은 기준이 아닙니다代码量不是标准

AI가 많은 코드를 만들었더라도 학생이 결과를 확인하고 판단한 근거를 설명할 수 있어야 합니다.就算 AI 写了很多代码，学生也要说得出自己确认结果、做出判断的依据。

7. 안전7. 安全13-2

안전과 개인정보를 확인한다确认安全与个人信息 핵심核心

  • 실제 개인정보와 민감정보를 사용하지 않았다.没有使用真实的个人信息与敏感信息。
  • 비밀번호·API 키·토큰이 프로젝트에 없다.项目里没有密码、API 密钥、令牌。
  • 잘못된 입력을 그대로 처리하지 않는다.不会把错误输入照单全收。
  • 오류 화면과 로그에 비밀정보가 보이지 않는다.错误画面与日志里看不到机密信息。
  • 파일 업로드가 있다면 교사가 허용한 형식·크기·저장 위치를 사용한다.若有文件上传，只用老师允许的格式、大小与保存位置。
  • 다른 학생과 다른 프로젝트의 데이터에 접근하지 않는다.不去访问其他学生与其他项目的数据。
1회에서 정한 세 가지第 1 次课定下的三件事

1회에 ① 마음껏 써도 되는 것 · ② 반드시 확인할 것 · ③ 넣지 않을 것을 나누었습니다. 이 목록은 그중 ③에 해당하는 것들입니다. 마지막 시간에도 같은 기준입니다.第 1 次课把东西分成了① 尽管用的 · ② 必须确认的 · ③ 不放进去的。这份清单就是其中的③。最后一节课，标准还是同一个。

8. 제출 확정8. 确认提交13-2

최종 제출을 확정한다确认最终提交 실습实践

제출 순서提交顺序
  1. 교사가 안내한 제출 위치에서 파일명과 학생 정보를 확인한다.在老师指定的提交位置确认文件名与学生信息。
  2. 최종 버전의 로컬 또는 플랫폼 실행 상태를 확인한다.确认最终版本在本地或平台上的运行状态。
  3. PRD·개발 계획·테스트 기록이 프로젝트에 포함되었는지 확인한다.确认 PRD、开发计划、测试记录都在项目里。
  4. 플랫폼을 사용하는 경우 ‘최종 제출 확정’을 선택하고, 대체 제출인 경우 교사의 확인을 받는다.使用平台的选“确认最终提交”；用替代方式的，请老师确认。
  5. 제출 시각과 최종 버전 번호를 기록한다.记下提交时间与最终版本号。
  • 제출한 파일명提交的文件名
  • 제출 시각提交时间
  • 최종 버전 번호最终版本号
  • 제출 방식 (플랫폼 / 대체)提交方式（平台 / 替代）

  • 플랫폼 또는 로컬에서 최종 프로젝트가 실행된다.在平台或本地最终项目能跑起来。
  • 대표 사용자 흐름을 처음부터 핵심 결과까지 실행했다.从头到核心结果跑通了代表性用户流程。
  • 핵심 예외 뒤 다시 시도할 수 있는지 확인했다.确认了核心例外之后能否重试。
  • SQLite에 핵심 기록이 저장되고 다시 보이는지 확인했다.确认了核心记录存入 SQLite 且能再看到。
  • PRD와 실제 결과의 관계를 설명했다.说明了 PRD 与实际结果的关系。
  • 9회의 사용자 흐름과 범위 조정 내용을 설명했다.说明了第 9 次课的用户流程与范围调整。
  • 화면·API 요청·응답·SQLite 저장·조회의 연결을 자신의 서비스로 설명했다.用自己的服务说明了画面、API 请求·响应、SQLite 保存·查询的连接。
  • 테스트 결과를 근거로 한 수정 과정을 설명했다.说明了以测试结果为依据的修改过程。
  • AI가 한 일과 학생이 판단·확인한 일을 구분했다.区分了 AI 做的事与学生判断、确认的事。
  • 개인정보·비밀정보와 안전 조건을 확인했다.确认了个人信息、机密信息与安全条件。
  • 최종 프로젝트 ZIP과 문서 기록을 제출했다.提交了最终项目 ZIP 与文档记录。
이수 기준에 없는 것不在修毕标准里的

코드의 양, 기능 수, 화면의 화려함, 테이블 수, DB 구조의 복잡함과 오류를 한 번도 만나지 않았는지는 이수 기준에 포함하지 않습니다.代码量、功能个数、画面花哨程度、表的数量、数据库结构的复杂度，以及是否一次错误都没碰上，都不列入修毕标准。

10. 마치며10. 结语13-2

13주 과정의 완료 지점13 周课程的终点

여러분이 한 일你们做过的事
  • 서비스 아이디어를 PRD로 정리했다.把服务想法整理成了 PRD。
  • 사용자 흐름과 구현 가능한 범위를 확정했다.确定了用户流程与可实现的范围。
  • AI와 함께 실제 서비스를 만들었다.和 AI 一起做出了真实的服务。
  • 핵심 기록이 SQLite에 저장되고 다시 보이는지 확인했다.确认了核心记录存进 SQLite 并能再看到。
  • 사용자 흐름 테스트를 근거로 수정했다.以用户流程测试为依据做了修改。
  • 최종 결과를 실행하고 설명하고 제출했다.把最终结果跑了、讲了、交了。
남는 것留下的

이 수업에서 배운 도구는 언젠가 바뀝니다. Python도, Next.js도, 지금 쓰는 AI도 바뀔 것입니다. 그러나 “무엇을 만들지 정하고, 결과를 확인하고, 근거를 가지고 판단하는 방법”은 바뀌지 않습니다.这门课里学的工具，总有一天会变。Python 会变，Next.js 会变，现在用的 AI 也会变。可是“决定要做什么、确认结果、带着依据做判断”的方法不会变。

여러분은 이제 읽고 판단할 수 있는 사람입니다. 그것이 이 13주의 결과입니다.你们现在是能读、能判断的人了。这就是这 13 周的成果。
