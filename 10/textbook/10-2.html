1. 시작 상태1. 起始状态10-2

터미널 두 개로 시작한다 — 실행용과 OpenCode용用两个终端开始 — 一个运行，一个给 OpenCode 실습实践

오늘은 서비스를 켜 둔 채로 AI와 이야기합니다. 서비스를 켠 터미널은 계속 일하고 있어서 거기에 다른 명령을 칠 수 없습니다. 그래서 터미널을 하나 더 엽니다. 두 터미널이 무엇을 하는지 구분해 두면 오늘 막히는 일이 절반으로 줄어듭니다.今天要在服务开着的状态下和 AI 对话。开着服务的终端一直在工作，没法在里面输入别的命令。所以再开一个终端。分清两个终端各做什么，今天卡住的情况就能少一半。

순서顺序
  1. VS Code에서 10 폴더를 연다. 탐색기 맨 위에 10, docs 안에 파일 다섯 개가 있는지 본다.在 VS Code 里打开 10 文件夹。看资源管理器最上面是不是 10，docs 里有没有五个文件。
  2. 터미널 ①: npm run dev → 브라우저에서 localhost:3000을 열어 예시 화면이 보이는지 본다.终端 ①：npm run dev → 在浏览器打开 localhost:3000，看示例画面是否出现。
  3. 터미널 오른쪽 위의 +를 눌러 터미널 ②를 연다. 줄 끝이 …\10>인지 본다.点终端右上角的 +，打开终端 ②。看行末是不是 …\10>。
  4. 터미널 ②: opencode를 켠다.终端 ②：打开 opencode。
예시 화면이 안 열리면 코드를 고치지 않습니다示例画面打不开时，不要改代码

4. 다를 때4. 不一样时10-2

약속과 다르면 처음 달라진 한 단계만 고친다和约定不一样时，只改最先出偏差的那一步 핵심核心

화면이 약속과 다르게 움직이면 「안 돼, 다시 해 줘」라고 보내기 쉽습니다. 그러면 AI는 프로젝트를 크게 다시 만들고, 잘되던 부분까지 바뀝니다. 대신 원래 약속, 내가 한 행동, 실제로 보인 것을 그대로 전하고, 처음 달라진 한 단계만 고치게 합니다.画面和约定不一样时，很容易发一句“不行，重做”。那样 AI 会把项目大改一遍，连本来好好的部分都变了。应该把原来的约定、我做的动作、实际看到的照实告诉它，只让它改最先出偏差的那一步。

5. 아직 기억 못 함5. 还记不住10-2

서비스를 다시 켜 보고, 사라지는 것을 적는다重新打开服务，写下消失的东西 실습实践

핵심 행동이 약속대로 움직였다면 마지막으로 하나를 더 해 봅니다. 터미널 ①에서 Ctrl+C로 서비스를 멈췄다가 npm run dev로 다시 켜고 화면을 새로고침합니다. 방금 입력한 결과가 남아 있나요? 대부분은 사라집니다. 오늘의 API는 답만 하고 기억하지 않기 때문입니다.核心动作按约定跑通后，最后再试一件事：在终端 ① 按 Ctrl+C 停掉服务，再用 npm run dev 重新打开，刷新画面。刚才输入的结果还在吗？大多数都消失了。因为今天的 API 只会答复，不会记住。

내 버튼 하나가 요청과 응답으로 이어졌다自己的一个按钮接成了请求与响应

오늘은 AI에게 문서를 먼저 읽히고 계획을 듣고, 약속과 맞는지 확인한 뒤에야 연결을 맡겼습니다. 그리고 정상 입력과 잘못된 입력으로 직접 시험해, 내 서비스의 핵심 행동 하나가 화면 → 요청 → API → 응답 → 화면으로 이어지는 것을 확인했습니다.今天先让 AI 读文档、听它的计划，确认符合约定之后才让它去连接。然后用正常输入和错误输入亲手测试，确认了自己服务的一个核心动作接成了 画面 → 请求 → API → 响应 → 画面。

이번 차시에서 남길 것本课时要记住的
