2. API2. API10-1

API는 서비스 안의 약속된 창구다API 是服务里约定好的窗口 핵심核心

그림의 창구에서 종이는 아무 데로나 넣지 않습니다. 정해진 틈으로, 정해진 양식을 넣어야 답이 나옵니다. 서비스에서도 화면이 기능에게 일을 부탁할 때 이렇게 미리 정한 창구로 부탁합니다. 이 창구를 API라고 부릅니다.图里的窗口，纸不能随便往哪儿塞。要从规定的缝里、按规定的格式递进去，才会有答复。服务里也一样：画面请功能办事时，要通过这样事先定好的窗口来请求。这个窗口就叫 API。

APIApplication Programming InterfaceAPIApplication Programming Interface
현상现象
버튼을 누르면 잠깐 「보내는 중」이 보였다가 결과가 나타납니다. 그 사이에 화면은 서비스에 무언가를 보내고 답을 기다렸습니다.按下按钮后，会短暂显示“正在发送”，然后结果才出现。在这之间，画面向服务发出了什么，并在等答复。
쉬운 설명通俗说法
화면과 기능이 서로 부탁하고 답하는 약속된 창구입니다.画面和功能互相请求、答复的约定好的窗口。
정확한 정의准确定义
한 프로그램이 다른 프로그램에게 일을 요청할 때 쓰는 주소 · 방법 · 주고받는 데이터의 약속.一个程序请另一个程序办事时使用的地址 · 方法 · 收发数据的约定。
경계边界
API가 꼭 다른 회사의 서비스를 뜻하지는 않습니다. 오늘 보는 API는 내 프로젝트 안에 있는 창구입니다.API 不一定指别家公司的服务。今天看的 API 是自己项目里面的窗口。
문장 속 사용句中用法
“추가 버튼을 누르면 화면이 /api/tasks API에 할 일을 보낸다.”“按下添加按钮，画面就把待办发给 /api/tasks 这个 API。”
3. 요청3. 请求10-1

요청에는 어디로 · 어떻게 · 무엇을이 담긴다请求里装着 往哪里 · 怎么做 · 送什么 핵심核心

창구에 종이를 넣을 때 정해야 하는 것은 세 가지입니다. 어느 창구로 갈지, 무엇을 해 달라고 할지, 함께 무엇을 건넬지입니다. 오늘 받은 10 프로젝트에는 이 세 가지가 이미 정해진 예시 API가 하나 들어 있습니다.往窗口递纸时要定三件事：去哪个窗口、请它做什么、一起递过去什么。今天拿到的 10 项目里，已经有一个把这三件事定好的示例 API。

요청에 담기는 것请求里装的뜻意思예시 프로젝트에서는在示例项目里
어디로往哪里요청 주소请求地址/api/check/api/check
어떻게怎么做방법 — 보여 달라(GET)인지 처리해 달라(POST)인지方法 — 是“给我看”（GET）还是“帮我处理”（POST）POSTPOST
무엇을送什么함께 보내는 데이터一起发送的数据입력한 글자 text输入的文字 text
주소는 내가 처음부터 정하지 않습니다地址不用自己从头定

주소와 방법은 10-2에서 AI가 제안하면 내가 읽고 확인합니다. 오늘 내가 먼저 정할 것은 무엇을 보내고 무엇을 돌려받아야 하는지입니다.地址和方法到 10-2 由 AI 提出、由我读过确认。今天我先要定的是发送什么、该收回什么。

3. 요청3. 请求10-1

9회의 흐름을 요청과 응답으로 다시 읽는다用请求与响应重读第 9 次课的流程

9회의 사용자 흐름은 여전히 기준입니다. 다만 오늘은 「행동」과 「서비스의 반응」 사이에 숨어 있던 두 걸음을 꺼내 봅니다. 화면이 요청을 보내는 걸음과, API가 처리해 응답을 돌려주는 걸음입니다.第 9 次课的用户流程依然是标准。只是今天要把藏在“动作”和“服务的回应”之间的两步拿出来看：画面发出请求的一步，和 API 处理后送回响应的一步。

할 일 정리 서비스에서 추가를 누르면在待办整理服务里按下添加

4. GET과 POST4. GET 与 POST10-1

보여 달라는 GET, 처리해 달라는 POST“给我看”的 GET，“帮我处理”的 POST 핵심核心

요청의 방법은 여러 가지지만 이 수업에서는 두 가지만 구분합니다. 이미 있는 정보를 보여 달라는 요청과, 데이터를 보내 처리해 달라는 요청입니다. 이름을 외우기보다 내 기능이 어느 쪽인지 고를 수 있으면 됩니다.请求的方法有好几种，这门课只区分两种：请它给我看已有信息的请求，和发送数据请它帮我处理的请求。比起记名字，能判断自己的功能属于哪一种就行。

방법方法쉽게 말하면通俗说法예例子
GETGET이미 있는 정보를 보여 달라把已有的信息给我看저장된 할 일 목록 불러오기调出已保存的待办列表
POSTPOST데이터를 보내 처리해 달라发送数据，帮我处理새 할 일 추가 · 입력한 값으로 계산添加新待办 · 用输入的值计算
  • 버튼을 누를 때 사용자가 입력한 값이 함께 가는가? → 대개 POST按按钮时，用户输入的值会一起发过去吗？→ 通常是 POST
  • 화면을 열자마자 저장된 기록이 보여야 하는가? → 대개 GET一打开画面就要显示已保存的记录吗？→ 通常是 GET
5. JSON5. JSON10-1

요청과 응답은 이름 : 값으로 적힌다请求和响应用 名字 : 值 来写 핵심核心

화면과 API가 주고받는 종이에는 JSON이라는 형식으로 글이 적힙니다. 3-2에서 본 사전(dict)처럼 이름과 값이 짝을 이룹니다. 괄호와 쉼표를 직접 쓰는 연습은 하지 않습니다. 각 이름이 무슨 뜻인지 읽을 수 있으면 됩니다.画面和 API 来回传的纸上，内容是用 JSON 格式写的。像 3-2 学过的字典（dict）一样，名字和值成对出现。不练习自己写括号和逗号，只要能读懂每个名字是什么意思就行。

요청 — 화면이 보내는 것请求 — 画面发送的
{
  "text": "과학 보고서"
}
{
  "text": "과학 보고서"
}
응답 — API가 돌려주는 것 (성공)响应 — API 送回的（成功）
{
  "ok": true,
  "message": "받은 글자: 과학 보고서"
}
{
  "ok": true,
  "message": "받은 글자: 과학 보고서"
}
이름名字뜻意思
texttext사용자가 입력한 글자用户输入的文字
okok처리했는가 — true면 성공, false면 실패处理了吗 — true 成功，false 失败
messagemessage화면에 보여 줄 문장要在画面上显示的句子
6. 성공과 실패6. 成功与失败10-1

응답은 성공만이 아니라 실패도 알려 준다响应不只告诉成功，也要告诉失败 핵심核心

좋은 API는 잘될 때만 답하지 않습니다. 입력이 비었거나 틀렸을 때도 무엇이 문제인지 알려 줘야 사용자가 고쳐서 다시 할 수 있습니다. 9회에 적은 예외 흐름이 바로 이 실패 응답으로 만들어집니다. 응답의 종류는 세 가지로 나눠 봅니다.好的 API 不只在顺利时回答。输入为空或有错时，也要告诉用户问题在哪，用户才能改好重来。第 9 次课写的例外流程，就是用这种失败响应做出来的。把响应分成三种来看。

결과结果응답에 들어갈 것响应里要有的화면이 할 일画面要做的
성공成功성공했다는 표시와 결과成功的标记和结果사용자가 원한 결과를 보여 준다显示用户想要的结果
입력 문제输入问题무엇을 고쳐야 하는지要改什么고쳐서 다시 하는 방법을 알려 준다告诉用户怎么改好再试
서비스 문제服务问题처리하지 못했다는 것과 다시 해 볼 수 있다는 것没能处理，以及可以再试사용자 탓으로 돌리지 않는다不把责任推给用户
상태 번호는 외우지 않습니다状态码不用背

개발자는 실패에 400 같은 번호를 붙이기도 합니다. 이 수업에서는 번호보다 사용자가 다음에 무엇을 하면 되는지 알 수 있는가를 봅니다.开发者有时会给失败标上 400 之类的编号。这门课不看编号，而是看用户能不能知道下一步该做什么。

이제 설치가 끝났을 것입니다. 예시 프로젝트를 켜서 지금까지 읽은 요청과 응답이 실제로 오가는지 봅니다. 서비스를 켜 두는 터미널은 따로 하나 둡니다. 켜는 명령은 13회까지 같습니다.安装应该已经结束了。打开示例项目，看刚才读到的请求与响应是否真的在来回传。让服务一直运行的终端要单独留一个。启动命令到第 13 次课都一样。

순서顺序
  1. 터미널에 npm run dev를 입력한다. Ready가 보이면 된다.在终端输入 npm run dev。看到 Ready 就好了。
  2. 브라우저 주소창에 localhost:3000을 입력해 연다.在浏览器地址栏输入 localhost:3000 打开。
  3. 입력칸에 아무 글자나 쓰고 확인을 누른다. 초록 상자에 「받은 글자: …」가 나온다.在输入框里随便写几个字，按확인（确认）。绿色框里会出现“받은 글자：…”（收到的文字）。
  4. 입력칸을 비우고 확인을 누른다. 주황 상자에 「글자를 입력하세요.」가 나온다.清空输入框，按확인。橙色框里会出现“글자를 입력하세요.”（请输入文字）。
두 번 누른 것이 성공 응답과 실패 응답입니다按的两次，就是成功响应和失败响应

초록 상자는 ok: true 응답, 주황 상자는 ok: false 응답이 화면에 나타난 것입니다. 멈출 때는 이 터미널을 누르고 Ctrl+C를 누릅니다.绿色框是 ok: true 的响应，橙色框是 ok: false 的响应显示在画面上的样子。要停止时，点这个终端再按 Ctrl+C。

9. 내부와 외부9. 内部与外部10-1

이 수업의 API는 내 프로젝트 안에 있다这门课的 API 在自己的项目里

API라는 말을 들으면 날씨 정보나 ChatGPT처럼 다른 회사가 여는 창구를 떠올리기 쉽습니다. 그런 외부 API는 대개 가입과 키, 때로는 비용이 필요해서 이 수업에서는 쓰지 않습니다. 오늘부터 만드는 API는 화면과 같은 10 프로젝트 안에 있는 창구입니다.一听到 API，很容易想到天气信息或 ChatGPT 这类由别家公司开的窗口。这类外部 API 通常需要注册和密钥，有时还要花钱，所以这门课不用。从今天起做的 API，是和画面在同一个 10 项目里的窗口。

내부 API · 이 수업内部 API · 这门课
  • 내 프로젝트의 app\api 안에 있다在自己项目的 app\api 里
  • 가입·키·비용이 없다不需要注册·密钥·费用
  • 고치면 바로 내 화면에서 확인한다改了马上能在自己画面上确认
외부 API · 이 수업에서 쓰지 않음外部 API · 这门课不用
  • 다른 회사의 서버에 있다在别家公司的服务器上
  • 가입과 키가 필요하고, 비용이 들 수 있다需要注册和密钥，可能要花钱
  • 키가 새면 다른 사람이 내 이름으로 쓴다密钥泄露了，别人就会用我的名义去用
오늘의 API는 아직 기억하지 못합니다今天的 API 还记不住东西

요청을 받아 답은 하지만, 서비스를 다시 켜면 방금 보낸 내용은 남지 않습니다. 기록을 남기는 일은 11회에 SQLite를 붙여서 합니다.它能接收请求并答复，但服务重新打开后，刚才发送的内容不会留下。留下记录这件事，到第 11 次课接上 SQLite 再做。

10. 확인10. 确认10-1

흔한 오해와 확인 문제常见误解与确认题 확인确认

오늘 배운 말을 정리합니다. 오해 두 가지를 먼저 읽고, 확인 문제에 답을 먼저 말한 뒤 해설을 엽니다. 막히는 문제가 있으면 그 절로 돌아가 다시 읽습니다.整理一下今天学的说法。先读两个误解，再对确认题先说出答案，然后打开解析。答不上来的，就回到那一节再读一遍。

오해误解
“API는 다른 회사가 만든 서비스를 말한다.”“API 指的是别家公司做的服务。”
사실事实
내 프로젝트 안의 화면과 기능 사이에도 API가 있습니다. 오늘 본 /api/check가 그렇습니다.自己项目里画面和功能之间也有 API。今天看到的 /api/check 就是。
오해误解
“잘될 때만 응답하면 된다.”“只在顺利时回答就行。”
사실事实
실패 응답이 없으면 사용자는 무엇이 잘못됐는지 모른 채 멈춥니다. 9회의 예외 흐름이 실패 응답으로 만들어집니다.没有失败响应，用户就会不知道哪里出错而卡住。第 9 次课的例外流程就是用失败响应做出来的。
요청에 담기는 세 가지는 무엇인가?请求里装着哪三样？
해설 보기查看解析

어디로(요청 주소), 어떻게(GET 또는 POST), 무엇을(함께 보내는 데이터)입니다.往哪里（请求地址）、怎么做（GET 或 POST）、送什么（一起发送的数据）。

입력한 할 일을 추가하는 요청은 GET과 POST 중 무엇인가?添加输入的待办，用 GET 还是 POST？
해설 보기查看解析

POST입니다. 사용자가 입력한 데이터를 보내 처리해 달라는 요청이기 때문입니다.POST。因为这是发送用户输入的数据、请它处理的请求。

11. 정리11. 小结10-1

버튼 하나 뒤에 요청과 응답이 있다一个按钮背后有请求与响应

오늘은 13회까지 쓸 10 프로젝트를 받아 설치하고, 예시 API로 요청과 응답이 오가는 것을 직접 봤습니다. 그리고 내 서비스의 핵심 행동 하나를 docs\10_api_promise.md에 약속으로 적었습니다. 다음 차시에는 AI가 이 약속대로 내 서비스의 API를 연결합니다.今天拿到并安装了用到第 13 次课的 10 项目，用示例 API 亲眼看到了请求与响应的来回。还把自己服务的一个核心动作作为约定写进了 docs\10_api_promise.md。下一课时，AI 会照这个约定接上自己服务的 API。

이번 차시에서 남길 것本课时要记住的
  • API는 화면과 기능이 부탁하고 답하는 약속된 창구다.API 是画面和功能互相请求、答复的约定好的窗口。
  • 요청에는 어디로 · 어떻게 · 무엇을이, 응답에는 성공했는지와 보여 줄 결과가 담긴다.请求里有往哪里 · 怎么做 · 送什么，响应里有是否成功和要显示的结果。
  • 실패 응답은 사용자가 고쳐서 다시 할 방법을 알려 준다.失败响应要告诉用户怎么改好再试。
  • 서비스를 켜는 명령은 npm run dev, 멈추는 것은 Ctrl+C.启动服务的命令是 npm run dev，停止用 Ctrl+C。
다음 차시로进入下一课时

다음 차시에는 OpenCode에게 docs의 문서를 먼저 읽히고, 코드보다 약속을 먼저 설명하게 합니다. 약속이 맞으면 그때 연결을 맡기고, 정상 입력과 잘못된 입력으로 직접 시험합니다.下一课时，先让 OpenCode 读 docs 里的文档，让它先讲约定，而不是先写代码。约定对了，再让它去接上，然后用正常输入和错误输入亲自试。
