이런 장면这样的场景

테스트를 시작합니다. 두 번째 단계에서 버튼 글씨가 마음에 들지 않습니다. 고칩니다. 세 번째 단계에서 화면 배치가 어색합니다. 고칩니다. 그러다 기록이 사라집니다.开始测试。第二步觉得按钮上的字不好看，改了。第三步觉得排版别扭，又改了。改着改着，记录不见了。

이제 무엇 때문에 사라졌는지 알 수 없습니다. 버튼 때문인지, 배치 때문인지, 원래부터 그랬는지 모릅니다. 테스트하면서 계속 고쳤기 때문입니다.现在说不清是什么让它不见的。是按钮？是排版？还是本来就这样？因为一边测一边改。

오늘은 순서를 지킵니다. 먼저 버전을 고정하고, 끝까지 실행하고, 기록한 다음, 필요하면 한 가지만 고칩니다.今天要守住顺序：先固定版本，跑到底，记录下来，需要时只改一处。

오늘의 순서今天的顺序
  1. 테스트할 버전을 고정한다.固定要测的版本。
  2. 대표 정상 흐름 → 예외 회복 → 다시 방문 순서로 실행한다.按代表正常流程 → 例外恢复 → 再次访问的顺序跑。
  3. 문제에 우선순위를 매긴다.给问题排优先级。
  4. 표준 ZIP을 만들어 시험 제출한다.做出标准 ZIP 并试提交。
새 기능을 추가하지 않습니다不添加新功能

오늘도 새 기능은 추가하지 않습니다. 핵심 흐름을 전혀 완료할 수 없는 문제만 한 가지씩 고칩니다.今天同样不加新功能。只针对完全走不完核心流程的问题，一次改一个。

1. 버전 고정1. 固定版本12-2

테스트할 버전을 고정한다固定要测试的版本 실습实践

테스트 중 기능을 계속 추가하면 어떤 결과를 확인했는지 알 수 없습니다. 먼저 현재 상태를 적어 둡니다.测试途中不断加功能，就说不清自己确认的是哪个结果了。先把当前状态写下来。

  • 프로젝트 폴더项目文件夹
  • 테스트 기록 파일测试记录文件
  • 테스트 시작 시각测试开始时间
  • 대표 사용자 흐름代表性用户流程
  • 저장할 핵심 기록要保存的核心记录
  • 저장된 기록을 다시 보는 순간再看已存记录的时刻
  • 지금 끝까지 이어지는 흐름目前能走通的流程
  • 아직 불완전한 흐름还不完整的流程
불완전해도 괜찮습니다不完整也没关系

아직 안 되는 흐름이 있어도 그대로 적습니다. 지금 어디까지 되는지를 아는 것이 오늘의 출발점입니다.还走不通的流程也照实写。知道现在能到哪一步，就是今天的起点。

2. 정상 흐름2. 正常流程12-2

대표 정상 흐름을 처음부터 실행한다从头跑一遍代表性正常流程 실습实践

실행 순서执行顺序
  1. 프로젝트를 완전히 중지했다가 다시 실행한다.把项目彻底停掉再重新启动。
  2. 처음 방문한 사용자처럼 첫 화면을 연다.像第一次来的用户那样打开首屏。
  3. 안내만 보고 무엇을 해야 하는지 확인한다.只看提示，确认该做什么。
  4. 9회에 정한 대표 행동을 순서대로 실행한다.按第 9 次课定的代表行动依次执行。
  5. 핵심 결과에 도달하는지 확인한다.确认能否到达核心结果。
  6. 단계별 예상 반응과 실제 결과를 기록한다.逐步记下预期反应与实际结果。
익숙하다고 건너뛰지 않습니다别因为熟就跳过

내가 만든 서비스는 익숙해서 설명을 건너뛰게 됩니다. 안내 문구를 읽지 않고 바로 버튼을 누르면, 안내가 이해되는지 확인할 기회를 잃습니다. 처음 사용하는 사람의 관점으로 확인합니다.自己做的服务太熟，容易跳过说明。不读提示直接点按钮，就失去了检验提示是否好懂的机会。要用初次使用者的视角来看。

기록은 12-1 양식 2·3절에记录写进 12-1 样式的第 2·3 节

시나리오별 결과는 양식 2절에, 단계별 확인은 3절에 적습니다.按场景的结果写在样式第 2 节，逐步确认写在第 3 节。

3. 예외 회복3. 例外恢复12-2

예외 뒤 회복 흐름을 실행한다跑一遍例外之后的恢复流程 실습实践

실행 순서执行顺序
  1. 9회에 정한 잘못된 입력이나 상황을 만든다.造出第 9 次课定的错误输入或情形。
  2. 서비스가 이유와 고칠 방법을 알려 주는지 확인한다.确认服务有没有说明原因与改法。
  3. 안내에 따라 값을 고친다.照提示把值改过来。
  4. 같은 핵심 행동을 다시 실행한다.再做一次同样的核心行动。
  5. 정상 결과까지 도달하는지 확인한다.确认能否走到正常结果。
5번이 이 절의 목적입니다第 5 步才是这一节的目的

오류 안내가 보이는 데서 끝나지 않고 사용자가 정상 흐름으로 돌아올 수 있어야 합니다. 2번까지만 확인하고 통과로 적는 일이 가장 흔한 실수입니다.错误提示不能只是出现就完了，用户得回得到正常流程。只确认到第 2 步就记成通过，是最常见的错误。

이런 경우는 실패입니다这些算失败사용자가 겪는 일用户遇到的情况
안내가 아예 없다完全没有提示무엇이 잘못됐는지 모른다不知道哪里出了错
안내는 있지만 이유가 없다有提示但没说原因무엇을 고쳐야 할지 모른다不知道该改什么
고쳤는데 입력칸이 사라졌다改好了输入框却没了다시 시도할 수 없다无法重试
처음부터 다시 시작해야 한다得从头再来중간에 그만둔다半路放弃
4. 다시 방문4. 再次访问12-2

반복 사용과 다시 방문을 확인한다确认反复使用与再次访问 실습实践

① 정상 흐름으로 기록 한 개를 만든다① 用正常流程造出一条记录
▼
② 새로고침하고 기록을 다시 확인한다② 刷新，再看一次记录
▼
③ 프로젝트를 다시 실행하고 같은 기록을 확인한다③ 重启项目，再看同一条记录
▼
④ 화면의 기록과 SQLite Viewer의 값을 비교한다④ 比对画面上的记录与 SQLite Viewer 里的值
②와 ③은 다릅니다②和③不一样

새로고침은 화면만 다시 그리는 것이고, 다시 실행은 프로그램을 껐다가 켜는 것입니다. 새로고침에서만 살아남는 기록은 메모리에만 있고 SQLite에는 없는 기록입니다.刷新只是重画画面，重启是把程序关掉再开。只在刷新时还在的记录，是只存在内存里、没进 SQLite 的记录。

④가 증거입니다④是证据

화면에 보이는 값과 SQLite Viewer의 표에 있는 값이 같다면, 기록이 실제로 파일에 남았다는 뜻입니다. 11-2에서 확인한 방법 그대로입니다.画面上的值与 SQLite Viewer 表里的值一致，就说明记录真的落到文件里了。方法与 11-2 确认过的一样。

5. 선택 테스트5. 可选测试12-2

필요한 경우만 선택 테스트를 한다只在需要时做可选测试 확장拓展

  • 분명한 입력 범위가 있으면 가장 작거나 큰 값을 확인한다.有明确的输入范围，就试最小值与最大值。
  • 파일 업로드를 승인받았다면 교사가 제공한 안전한 파일만 사용한다.获批做文件上传的，只用老师提供的安全文件。
  • 계획에 없는 전문 보안 테스트와 공격 코드는 만들지 않는다.计划之外的专业安全测试与攻击代码，一概不做。
해당하지 않으면 건너뜁니다不适用就跳过

내 서비스에 입력 범위 제한이 없고 파일 업로드도 없다면, 양식 4절은 “해당 없음”이라고 적고 넘어갑니다. 빈칸을 억지로 채우지 않습니다.自己的服务没有输入范围限制，也没有文件上传，就在样式第 4 节写“不适用”然后跳过。不必硬填空格。

시간이 남을 때만有余力再做

2~4절이 모두 통과한 다음에 합니다. 대표 흐름이 아직 막혀 있다면 여기에 시간을 쓰지 않습니다.要等第 2~4 节全通过之后再做。代表流程还卡着，就别把时间花在这里。

핵심 흐름을 전혀 완료할 수 없는 문제는 12회에도 한 가지씩 수정할 수 있습니다. 나머지는 기록만 하고 13회로 넘깁니다.完全走不完核心流程的问题，第 12 次课也可以一次改一个。其余的只记录，留到第 13 次课。

수정한 뒤에는 반드시 다시改完必须再跑

수정한 뒤 같은 행동과 대표 정상 흐름을 다시 실행합니다. 하나를 고치다가 다른 곳이 막히는 일이 자주 있습니다.改完之后，再跑一遍同样的行动和代表性正常流程。改好一处却堵住另一处，很常见。

7. 우선순위7. 优先级12-2

사용자 영향으로 문제의 우선순위를 정한다按对用户的影响给问题排优先级 핵심核心

① 13회에 반드시 고칠 문제① 第 13 次课必须改的

  • 사용자가 서비스를 시작할 방법을 알 수 없음用户不知道怎么开始用这个服务
  • 핵심 행동을 실행할 수 없음核心行动做不了
  • 행동 뒤 결과가 나타나지 않거나 목적과 다름行动之后没有结果，或结果与目的不符
  • 예외 안내 뒤 다시 시도할 수 없음看到例外提示后无法重试
  • 저장되어야 할 기록이 사라지거나 다시 보이지 않음本该保存的记录消失或再也看不到
  • 개인정보·비밀정보와 안전 문제个人信息、机密信息与安全问题

② 시간이 있으면 개선할 부분② 有时间再改的

  • 이해하기 어려운 안내와 버튼 표현难懂的提示语与按钮文字
  • 결과의 의미가 불분명한 부분结果含义不清楚的地方
  • 불필요한 예시 문구와 작동하지 않는 요소多余的示例文字与点了没反应的元素
  • 핵심 흐름을 방해하는 화면 배치妨碍核心流程的画面布局

③ 이번 수업에서는 남겨 둘 한계③ 这门课里留作局限的

핵심 목적에 영향을 주지 않으면서 시간이 많이 필요한 기능이나 표현을 기록합니다. 남겨 두기로 정한 것도 적어 두면 판단의 기록이 됩니다.把不影响核心目的却很费时间的功能或表达记下来。决定留下的东西，写下来就成了判断的记录。

12회 것은 시험 제출용입니다第 12 次课这份是试提交用的

12회에는 시험 제출 버전으로 사용하고, 13회에 수정한 뒤 같은 표준 파일명으로 새 버전을 만듭니다. 파일명은 바뀌지 않습니다.第 12 次课当作试提交版本用，第 13 次课改完后用同样的标准文件名做新版本。文件名不变。

완료 확인完成确认

  • 예외 상황 뒤 정상 흐름으로 돌아오는지 확인했다.确认了例外之后能否回到正常流程。
  • 반복 사용과 다시 방문 뒤 저장된 기록을 확인했다.确认了反复使用与再次访问后已保存的记录。

11. 정리11. 小结12-2

핵심 정리核心小结

이번 차시에서 남길 것本课时要记住的
  • 테스트 전에 버전을 고정해야 결과를 해석할 수 있다.测试前固定版本，结果才解释得清。
  • 정상 흐름 → 예외 회복 → 다시 방문 순서로 실행한다.按正常流程 → 例外恢复 → 再次访问的顺序跑。
  • 예외 안내가 보이는 것으로 끝이 아니라 정상 흐름으로 돌아와야 통과다.例外提示出现了还不算完，要能回到正常流程才算通过。
  • 새로고침과 다시 실행은 다르며, SQLite Viewer 비교가 기록의 증거다.刷新与重启不同，与 SQLite Viewer 的比对是记录留下的证据。
  • 문제는 사용자에게 미치는 영향으로 나눈다. 위에서부터 고친다.问题按对用户的影响分级，从上往下改。
  • 제출 ZIP에는 PRD · 개발 계획 · 테스트 기록이 들어간다.提交的 ZIP 里要有 PRD · 开发计划 · 测试记录。
  • 비밀번호와 개인정보, node_modules는 넣지 않는다.密码、个人信息与 node_modules 不要放进去。
  • 12회가 끝나면 제출 후보 · 테스트 기록 · 13회 수정 목록이 있어야 한다.第 12 次课结束时，应当有提交候选 · 测试记录 · 第 13 次课的修改清单。
